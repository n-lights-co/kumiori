# Unsupported Features and Known Limitations (Backlog)

A list of the features Kumiori does not have yet and of its known limitations. Update "Status" when work starts, and set "Status" to "done" when finished (rows are kept as history).
Sources: the conversion report over publicly available XSL-FO samples, and notes taken while implementing each feature. Item-by-item support status against the specifications is in the Conformance Guide (`docs/conformance/`, Japanese).

**Still unsupported or partial (summary)**: verification of conformance to the PDF/X standard (ISO 15930) (O-03). CGM GDP and POLYSYMBOL are not drawn because nothing is registered for them (I-09). The CCITTFaxDecode filter of EPS (PostScript) is not implemented (I-03). Rows whose status is "mostly done" or "partially done" also have remaining items. See the notes in each row for details.
Priority: **high** = frequent in the samples and in real documents / **medium** = appears occasionally / **low** = rare, or a workaround exists.

## Typesetting engine

| ID | Item | Priority | Status | Notes |
|----|------|--------|------|------|
| E-01 | `keep-with-next` / `keep-with-previous` | high | done | The first block of the run is trial-typeset, and the page is broken only when the start of the following block would not land on the same page. Values are always and integers of 1 or more (differences in strength are not distinguished). When what follows is inline (text or an image), it is kept on the same page as the start of an anonymous block made of the following inlines. Keeps on tables are covered in S-08. Column-level decisions are unsupported |
| E-02 | `text-align-last` | high | done | start / center / end / justify. `relative` and unspecified behave as before |
| E-03 | Border styles (dotted, dashed, double) | high | done | dotted / dashed / double / groove / ridge / inset / outset (the corners of 3D borders, and of solid borders of different colors, are mitered diagonally; the dash and dot patterns (the lengths of the marks and gaps) are derived from the border width) |
| E-04 | Underline and strikethrough (`text-decoration`) | medium | done | `TextStyle.textDecoration` (underline / overline / line-through and no-*). In vertical writing the underline is on the left of the line. Inline borders (a frame around text) are laid out in `inlineFlatten.ts` (when an inline crosses lines, the border on the side of the break is not drawn) |
| E-05 | Reflect `baseline-shift` in the line height and line spacing | low | done | super / sub / length. The shifted character's line-height area (the character's top and bottom plus the half-leading from its line-height) is shifted, and the line is widened by the amount that protrudes from it (line-height-shift-adjustment="consider-shifts"; since the half-leading is included, lines with superscripts and subscripts grow by the shifted amount) |
| E-06 | Floats protruding into the margin area (`marginal-notes-*`) | medium | done | Marginal notes: a float that protrudes into the margin via a negative start/end-indent is placed in the margin without encroaching on the body text (`LFloat.marginal`). The float's inside / outside is decided by page parity, and it is relaid out if moved to the next page. Along the way, the margin shorthand (2–4 values) of page master / region-body was fixed |
| E-07 | Per-page footnote-number reset | medium | done | `FootnoteOptions.reset: 'page'` (axf:footnote-number-reset="page"). Renumbers by the order within the page where each footnote was placed in the previous pass, and re-typesets until the placements stop changing. The automatic footnote-number extensions (axf:footnote-number / -citation / -format / -initial) are also supported |
| E-08 | Footnotes: output of footnote bodies inside tables and containers | medium | done | When a line inside a cell, block-container or float has a footnote, it is stacked into the footnote area of the page on which the parent placed that box (footnotes in repeated table headers only once). The fit test for the line does not include the footnote height (if it does not fit, the footnote is split / moved to the next page) |
| E-09 | Footnotes: splitting footnotes that contain nested blocks across multiple pages | low | done | Descends into the nested blocks and splits by line (the split block drops the border and padding on the cut side) |
| E-10 | Multi-column: columns inside a block-container (`axf:column-count`) | medium | done | `LBlockContainer.columns` (axf:column-count / column-gap / column-rule-* / column-rule-display). With a specified height the columns are filled in order; without one the column heights are balanced. A container without a specified height, border or rotation continues its columns across pages when it does not fit on the page (`layoutColumnsPaged`). Other containers do not cross pages (footnote bodies inside them are not output) |
| E-11 | Multi-column: column rules (`axf:column-rule`) | low | done | `PageMaster.columns.rule` (axf:column-rule-width/style/color) |
| E-12 | Multi-column: place before-floats and footnotes in an area spanning all columns | high | done | The default is per page (full width). `axf:footnote-position="column"` makes it per column. The float is placed at the top of the page rather than below a span="all" heading |
| E-13 | Multi-column: option to balance the columns at the end of the flow | low | done | `PageMaster.columns.fill: 'balance'` (the region-body's `axf:column-fill` / `column-fill="balance"`) also balances the columns at the end of the flow. The default is only just before a span |
| E-14 | Relayout when the inline-direction size differs between conditional page masters | low | done | When the body width changes at a page break, the widths of the open boxes are recomputed and the rest of the paragraph is relaid out line by line at the new width (boxes with a specified width and table column widths are left as they are) |
| E-15 | Tables: splitting within a row, `border-collapse`, repeating `table-footer` | medium | mostly done | Row splitting (a row that does not fit on the page has its cell contents split by line; keep-together rows are moved), table-footer repetition, table-omit-header/footer-at-break. border-collapse is S-01. Automatic column widths (tables without width specifications) are distributed in proportion to each column's maximum length when they do not fit (XSL-FO). A cluster of rows containing rowSpan is moved without splitting if it fits on one page; if not, the spanning cells are divided into per-row cells (the contents go in the first row, and the borders between them are removed) and the cluster crosses the page at a row boundary (the contents of a spanning cell themselves are never split partway) |
| E-16 | Page splitting of blocks whose writing mode is orthogonal to the parent's | low | done | Blocks without an inline-direction size (e.g. vertical text inside horizontal text): the line length is the remaining page height, lines are stacked up to the parent's width, and lines that do not fit continue in a fragment on the next page. Blocks with a specified size, and block-containers, are not split, as before |
| E-17 | Compression of consecutive punctuation, ruby overhang, spacing between Japanese and Latin text, kerning | medium | done | Compression of consecutive punctuation (」「, 。」, （「) and spacing between Japanese and Latin text (a quarter em), ruby overhang (`rubyOverhang`; up to one ruby character over the adjacent kana and punctuation; not at the line start or end, and not over kanji), pair kerning (`kerning`; Latin text in horizontal writing, from the font's kern / GPOS). In compatibility mode the defaults are compression, spacing and overhang on, kerning off |
| E-18 | Kinsoku: long runs of punctuation that cannot start a line | low | done | When there is no break opportunity to back up to, the text up to the next break opportunity (within 12 characters) is pushed in by compressing the punctuation spacing within the line (half of a full-width bracket, period or comma) (pulling in). If it still does not fit after compression, forced break as before |
| E-19 | `float` positioned relative to nested blocks, floats with a writing mode different from the parent's | low | done | A float whose writing mode is orthogonal to its parent's is laid out in its own writing mode, placed at the edge, and the body text wraps around its physical size (the default line length is the remaining page). Positions are relative to the edge of the reference area (body region or block-container), as the spec says, and not to the edge of the nested block |
| E-20 | `last-ending-within-page` for `marker` | low | done | Per XSL 1.1 §6.13.6 and §7.25.4: the last marker whose parent ends on the page; otherwise the last marker whose parent has an area on the page; otherwise carried over. The end of a parent inside a separate flow such as a block-container is not recorded (it is treated as the last marker on its page) |

## XSL-FO import

| ID | Item | Priority | Status | Notes |
|----|------|--------|------|------|
| I-01 | Numeric `reference-orientation` on `page-sequence`, values other than multiples of 90 | low | done | A numeric value on page-sequence overrides the orientation of the body (region-body) (from-page-master-region() uses the region-body's value). Values other than multiples of 90 are not permitted by the spec, so they are reported and treated as 0 |
| I-02 | `fo:instream-foreign-object` (inline SVG, MathML) | medium | mostly done | SVG becomes a data-URI image (vector in PDF). Accent arrows and radicals are also drawn with shapes and rules. Alignment marks (maligngroup), the placement that pushes equation numbers (mlabeledtr) to the line edge, and Content MathML are unsupported (for Content MathML the inner text is laid out in sequence). All of this is about the fallback used when the math font cannot be loaded (`foMathFallback.ts`); when formulas are typeset with the math font (STIX Two Math; `mathLayout.ts`), maligngroup, mlabeledtr and Content MathML are supported too. | I-03 | WMF / EMF / EPS images | low | done | WMF and EMF are converted to SVG and drawn (clipping, world transforms, arcs, DIBs, ALPHABLEND, palettes, pattern brushes; raster operations that mix with the destination are done with blend modes when the source is black and white; hatching uses the user-specified 8-pixel spacing). EPS is converted to SVG by executing the PostScript (shapes, images, colors, text; text uses the glyph shapes of the embedded fonts: Type 1, Type 3, CIDFontType 0, CFF). Shadings (shfill and PatternType 2; ShadingType 1 to 7, FunctionType 0, 2 and 3 and procedures) are drawn as pixel images, and tiling patterns (PatternType 1) as copies of the PaintProc drawing. Pattern strokes (stroke in the Pattern color space) compute the outline of the stroke (reflecting the width, caps, joins, dashes and miter limit) and fill that shape with the pattern. Shadings, functions and tiling patterns share their definitions with PDF and were checked against ISO 32000-2:2020 §7.10, §8.7.3 and §8.7.4 (Order 3 of sampled functions is a natural cubic spline when there is one input and four or more samples, and linear interpolation otherwise). **Remaining**: the CCITTFaxDecode filter (fax coding; PLRM §3.13.3) is not implemented (the filter operator raises the undefined error and what was drawn up to that point is drawn). Encoding filters other than NullEncode are not implemented either |
| I-04 | `axf:*` extensions (background images, forms, line numbers, annotations, etc.) | medium | done | Supports axf:document-info, bookmarks, background images, column rules, links (fo:basic-link), annotations (Text, FreeText, Stamp), line numbers (axf:line-number-*), rounded corners (axf:border-radius; the same for all four corners) and shadows (axf:box-shadow; offset, blur, spread and color). Also revision bars (axf:revision-bar-*), diagonal and reverse-diagonal borders (axf:diagonal-border-* / axf:reverse-diagonal-border-*) and forms (axf:form / axf:form-field; PDF AcroForm fields). Per-corner radii (axf:border-top-left-radius etc.) and the listbox top-index (axf:field-top-index) are supported too, as are file attachment annotations (axf:annotation-type="FileAttachment"; the file in axf:annotation-file-attachment is embedded in the PDF with the icon from axf:annotation-icon-name; ISO 32000-2 §12.5.6.15 and §7.11.4) and the rollover (R) and down (D) appearances of push buttons (§12.5.5) |
| I-05 | Content other than a leader in `fo:footnote-separator` (text, images) | low | done | A separator with text, images (external-graphic / instream-foreign-object), a background color or borders is laid out as content at the width of the footnote area. A leader-only separator is handled the same way (the leader is typeset as in body text: solid / dotted, length, thickness). An empty separator gets the default separator rule |
| I-06 | `font-stretch` | low | done | `TextStyle.fontStretch` (keywords use the CSS ratios; percentages; wider / narrower). Since no fonts of differing widths are available, the glyphs are scaled horizontally in horizontal writing (vertical writing is unchanged) |
| I-07 | Actual fonts for specified families such as MS Mincho / MS Gothic | medium | done (via loading) | Choose a TTF / OTF / TTC with "Load font" (「書体を読み込む」) in the web app. Not bundled. Bold is drawn as synthetic bold (thickening the glyph outlines) when the font has no bold face. OpenType CFF fonts (OTF) are embedded as subset fonts with the unused glyphs emptied (CID-keyed fonts, where CID and GID differ, were verified with poppler to render identically to the original font) |
| I-08 | Finer behavior of `inline-container` other than for ruby | low | done | In addition to shrink-to-fit and first-line baseline alignment, supports display-align (placement within a fixed height), overflow="hidden" clipping, and alignment-baseline (central / before-edge / after-edge) (horizontal lines) |
| I-09 | CGM elements not yet drawn | low | done | Checked against the text of ISO/IEC 8632-1:1999 (including Technical Corrigenda 1 and 2) and 8632-3:1999. Supported: CELL ARRAY (local colour precision, packed and run-length lists, TRANSPARENT CELL COLOUR), tile arrays (TILE and BITONAL TILE; uncompressed, run length, T.4, T.6), HYPERBOLIC / PARABOLIC ARC, NON-UNIFORM (RATIONAL) B-SPLINE, CONNECTING EDGE, patterns (PATTERN TABLE, PATTERN SIZE), geometric patterns, triangular INTERPOLATED INTERIOR (filled with pixels), HATCH STYLE DEFINITION, LINE AND EDGE TYPE DEFINITION, TEXT PATH (left, up, down), and segments (BEGIN / END SEGMENT, COPY SEGMENT, SEGMENT TRANSFORMATION). Version 3 and 4 elements are supported too: bundles (LINE / MARKER / TEXT / FILL / EDGE REPRESENTATION and ASPECT SOURCE FLAGS; bundle indexes not in the table use the individual values), INHERITANCE FILTER (state-list attributes take their values at the time of COPY SEGMENT), the CIELAB, CIELUV and RGB-related colour models (the scale and offset of COLOUR VALUE EXTENT and the reference white of COLOUR CALIBRATION), character sets (CHARACTER SET LIST, CHARACTER CODING ANNOUNCER, CHARACTER SET INDEX and ALTERNATE CHARACTER SET INDEX; ISO 2022 designations, JIS X 0208, JIS X 0201, GB 2312, KS C 5601, ISO/IEC 8859, UTF-8, etc.), COMPOUND LINE, COMPOUND TEXT PATH and GENERALIZED TEXT PATH MODE (non-tangential and axis-tangential), TEXT SCORE TYPE (right, left and through scores and kendot), RESTRICTED TEXT TYPE (boxed-cap, boxed-all, isotropic-cap, isotropic-all and justified), LINE / EDGE TYPE CONTINUATION (continue, restart and adaptive continue) and INITIAL OFFSET, and MITRE LIMIT. The direction of the vertical TEXT ALIGNMENT (top, cap, half, bottom, continuous) was corrected. Of the items in the ISO International Register of Graphical Items, ESCAPE 22 (Transparent Cell Colour) and 45 (Alpha Transparency; the opacity of later primitives), colour models 6, 7 and 8 (RGB-alpha, sRGB, sRGB-alpha; the alpha component becomes the opacity of fills, lines, etc.) and TILE compression types 7, 8 and 9 (baseline JPEG, LZW, and PNG deflate with PNG filters) are supported (ESCAPE data records are read as SDRs; the numbers were checked against the WebCGM 2.1 tables and the notes in the standard; the register itself could not be read). | I-10 | Indexes (the `fo:index-*` elements, `index-key`, `index-class` and related; XSL 1.1 §6.10, §7.24) | medium | done | Collects the pages of keyed elements and ranges (`fo:index-range-begin`…`-end`) and builds the list of page numbers at `fo:index-page-citation-list` (duplicate removal, ranges of three or more consecutive pages, `index-class`, the three `merge-*` properties, replaceable separators and prefix/suffix, `page-number-treatment="link"`, `fo:folio-prefix` / `-suffix`). ## Differences from the XSL-FO 1.1 specification (spec review)

Differences found by checking against the text of the XSL 1.1 Recommendation (2006-12-05). § is the section number in the specification.

| ID | Item | Priority | Status | Notes |
|----|------|--------|------|------|
| S-01 | `border-collapse` on tables (§7.28.3; initial value collapse) | high | done | `LTable.borderCollapse` (the FO default is collapse). Adjacent cells merge into the right/bottom cell; on edges where the table has an outer border they merge into the outer border (`tableBorders.ts`). At a page break, the border between a repeated table header or footer and the first or last row on that page is chosen again from the borders of the rows that actually meet there (§6.7.3, §6.7.10) |
| S-02 | space derived from margin-top/bottom has `.conditionality=retain` (§5.3.2) | high | done | The block-start side of margins → retainSpaceBefore. The block-end side → retainSpaceAfter (spec mode only; compat mode discards it at the page end). space-after.conditionality="retain" is read in both modes. The last line of a paragraph is placed only if the retained space fits too (only the paragraph box's own space-after is counted, not those of enclosing boxes) |
| S-03 | `line-height` lengths and % are inherited as the computed length (§7.16.4) | high | done | `lineHeightPt` (inherited as a length) |
| S-04 | writing-mode: `tb-lr` mix-up, rl-tb / bt-* / lr/rl/tb, region placement by the page master's writing mode (§7.29.7, §6.4.15-18) | medium | done | Supports tb-lr (vertical-lr), the shorthands lr / rl / tb, region placement by the page's writing mode, and rl-tb and direction="rtl" (lines from the right; runs of Latin text and digits left to right; table columns from the right too). Ruby in vertical-lr goes on the left. Bidirectional text is ordered per UAX #9 (unicode-bidi and direction on inline and block are used too). Connected scripts such as Arabic are shaped by grouping the run and applying the font's glyph substitutions (horizontal writing). bt-lr, bt-rl, lr-bt, rl-bt, lr-alternating-*, lr-inverting-* and tb-lr-in-lr-pairs are typeset horizontally or vertically and then have an axis flipped (block-container, page-sequence and region-body). In bt-*, sideways Latin glyphs keep their top-to-bottom orientation; tb-lr-in-lr-pairs pairs are tate-chu-yoko (fitted to 1 em); flipping containers do not continue across pages |
| S-05 | `column` in break-before/after, blank pages for odd/even-page, `force-page-count`, auto-odd/auto-even for `initial-page-number` (§7.20.2, §7.27.6-7) | medium | done | `BreakKind` (page, column, odd-page, even-page). In multi-column layout, page leaves the remaining columns empty and goes to the next page. Blank-page insertion, `forcePageCount`, auto-odd/auto-even for initialPageNumber. break-before/after on tables is supported too |
| S-06 | White-space handling: linefeed-treatment / white-space-treatment / white-space-collapse independently, `wrap-option`, tabs (§7.16.7-8, 12-13) | high | done | `refineText`. The white-space shorthand (pre / nowrap / normal), wrap-option and zero-width spaces are supported too |
| S-07 | Indents inside elements that generate reference areas (block-container etc.) (§5.3.2) | medium | partially done | Only in spec mode (compat=spec) does it follow §5.3.2 (the inner elements inherit the container's start-indent from the content edge). Compatibility mode keeps the previous behavior (how a container inside an indented block is laid out is unverified). Along the way, the following points were fixed: the container's size is the content's size and its position the content's edge, page crossing of containers without a height, ipd.maximum, the default text-align is start, line breaks after a hyphen, compression of inter-word spaces, spacing between Japanese and Latin text at the line end, bold Latin text as Times-equivalent |
| S-08 | keep-together on table-row / list-item / table / block-container, keep strength, .within-line | medium | partially done | Supports keep-with-next/previous on table rows and list items, keep-together and keep-with-next on tables, and keep-together.within-line on inlines. Keep strengths (integer magnitudes) are not distinguished |
| S-09 | `display-align` on table-cell | high | done | display-align is inherited in the order table → row group → row → cell |
| S-10 | Pick up `id` from inline, wrapper, list-item, table-cell etc. too | medium | done | ids on inline, wrapper, table rows, cells, list items, block-containers, images and inline-containers. ids inside cells and containers are recorded on the page where they were placed |
| S-11 | font-size keywords (small came out as medium), the width of borders specified by style only (did not match medium), text-align left/right interpreted by writing mode | high | done | font-size keywords step by 1.2× from medium; style-only borders are medium (2.25pt). left/right are the same as start/end in lr-tb and in vertical writing, so no change (rl-tb is S-04) |
| S-12 | page-number `format` (§7.26.1), citation-last, last-ending-within-page, maximum-repeats / order / blank for page-sequence-master, region overflow clipping, provisional-label-separation, space precedence (§4.3), footnote citation formatting | low | done | Supports the page-number format, citation-last, page-sequence-master order / maximum-repeats / blank-or-not-blank (including parity blank pages in multi-column layout), overflow clipping, provisional-label-separation for label-end(), space precedence (§4.3.1), footnote citation formatting and last-ending-within-page (E-20) |
| S-13 | Switching between the spec's initial values and the compatibility-mode defaults (line pitch 1.2, hanging punctuation; justification is not the default) | medium | done | `ImportOptions.compat` (antenna / spec). "Typeset with the spec's default values" (「仕様どおりの既定値で組む」) in the web app |

## Output (Canvas / PDF)

The JIS X 4051 section and table citations in the sources, tests, docs and Conformance Guides were rewritten as JLREQ sections (unbreakable sequences §3.1.10, postfixed abbreviations A.13 cl-13, line-start prohibition §3.1.7 and its note, punctuation compression §3.1.4, ruby overhang §3.3.8, line adjustment §3.8), and the README lists "JLREQ (based on JIS X 4051)". JLREQ is not a standard, so conformance to JIS X 4051 itself has not been checked |
