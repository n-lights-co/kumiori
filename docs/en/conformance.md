# Kumiori Conformance Guide

For each element and property of XSL-FO 1.1, CSS and MathML, this document sets out side by side the definition and original text of the specification, how Kumiori handles it, an example typeset by Kumiori, and the code of that sample. Unsupported elements, properties and values are also listed by name. The documents themselves are written in their respective languages and typeset by Kumiori. The source paths below are relative to `docs/conformance/`.

| Document | Source | Contents |
| --- | --- | --- |
| XSL-FO 1.1 volume | `fo/kumiori-xsl-fo.fo` | XSL-FO elements and properties, MathML inside FO, image formats, unsupported elements and properties, and appendices on how the extensions for AH Formatter (axf:) are interpreted, the compatibility settings and the sources |
| HTML and CSS volume | `html/kumiori-html-css.html`, `html/kumiori-html-css.css` | CSS properties (pages, boxes, floats, fonts, text and lines, decoration, vertical writing, ruby, lists, tables, multi-column layout, flex and grid, page breaks and footnotes, images and formulas), unsupported properties, and appendices on the extensions for AH Formatter (including a list of -ah-), the compatibility settings and the sources |
| XSL-FO 1.1 volume (English) | `fo/kumiori-xsl-fo.en.fo` | English translation of the above (same samples; prose, tables, contents and bookmarks in English). `out/kumiori-xsl-fo.en.pdf` |
| HTML and CSS volume (English) | `html/kumiori-html-css.en.html` (shares the CSS) | English translation of the above (same samples). `out/kumiori-html-css.en.pdf` |

## How to build

```bash
npm run docs:conformance
```

The PDFs are produced in `docs/conformance/out/` (not kept in the repository; two volumes in Japanese and two in English). If `dist-cli` does not exist, run `npm run build:cli` first.

The typeset PDFs are attached to each GitHub release (publishing a release makes `.github/workflows/conformance-pdf.yml` typeset and attach them; see "For every release" in [`RELEASING.md`](RELEASING.md)).

- The version in the "Typesetting" row of the colophon is not written in the sources; the version in `package.json` is filled in when the documents are typeset (the `<?kumiori-version?>` and `<!--kumiori-version-->` marks in the sources). The PDFs attached to a release therefore show that release's version.
- The XSL-FO volume is typeset with the CLI's default `--compat spec` (XSL-FO 1.1 initial values).
- The fonts are Kumiori's defaults: Noto Serif JP and Noto Sans JP for Japanese, Tinos and Arimo for Latin, Cousine for monospace, and STIX Two Math for formulas. Kumiori fetches them from the distribution host.
- The typeset PDFs embed subsets of these fonts (only the glyphs used). Noto Serif JP, Noto Sans JP and STIX Two Math are licensed under the SIL Open Font License 1.1, and Tinos, Arimo and Cousine under the Apache License 2.0 (see "Fonts" in the README). The copyright in each font belongs to its copyright holders.

## How samples are written

Each sample is written once in the source, with marks before and after it.

- XSL-FO: `<?kumiori-sample id="name"?>` … `<?kumiori-sample-end?>`
- HTML: `<!--kumiori-sample id="name"-->` … `<!--/kumiori-sample-->`

The text between the marks is typeset as is (the typeset example). Before typesetting, `scripts/build-conformance.mjs` turns the original text between the marks into a code listing and inserts it after the typeset example. Writing `mark="string|string"` in the mark highlights those strings in the code listing. `test/conformance.test.ts` takes each sample, makes it a self-contained document that can be typeset on its own, typesets it and checks that no warnings are produced.

## How support is verified, and the generated parts

"Supported" (対応), "Partial" (一部) and "Unsupported" (未対応) are verified by loading into Kumiori a document that specifies the element or property and one that does not, and comparing what is passed to typesetting (the logical tree). Those for which specifying it does not change the content are treated as unsupported, and are listed by name in each document's "Unsupported …" chapter.

The section numbers, the table of contents, the property definition lines (the original text of the specifications' property tables, such as Initial, Applies to and Inherited), and the list of unsupported items are generated by scripts from the fetched specifications and written into the sources (between the `gen` marks; the scripts and the fetched specifications are not kept in the repository). The descriptions of the extensions (axf:, -ah-) and their value tables are Kumiori's own account of how it interprets them.

## Images

Of the images in `fo/images/` and `html/images/`, `woven.*` and `checker.png` are original drawings made with `scripts/make-conformance-images.py` (`woven.*` is the same drawing written out in the 12 formats Kumiori reads). `kumiori-logo.svg` is a copy of the logo in `assets/logo/`, and `arabic-sample.png` is an example of Arabic typeset by Kumiori (Section 8.4 of the HTML and CSS volume); the script does not make them.

- Raster: PNG, JPEG, GIF, BMP, TIFF, WebP (lossy and lossless)
- Vector: SVG, EPS, WMF, EMF, CGM

The raster images are written with Pillow. For the vector images, the script assembles the file contents directly.

```bash
python3 scripts/make-conformance-images.py
```

## Quotations

The text of the W3C specifications is quoted verbatim from the fetched originals. The sources and the dates of retrieval are recorded in the "Sources" appendix of each document. The copyright in the quoted text belongs to W3C; the "Sources" appendix also gives, for each document, the version retrieved, the copyright notice of the original document and its license, followed by the full texts of the licenses. Product manuals are not quoted.
