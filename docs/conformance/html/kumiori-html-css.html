はじめに

Kumiori (組み織り) は、HTML・CSS と XSL-FO から PDF を作る組版の処理系です。この文書は、CSS のプロパティを、ページ・ボックス・文字と行・縦書き・表・段組などの章に分けて取り上げ、Kumiori がそれをどう扱うかを、実際に組んだ例で示します。

1.1この文書の読み方

節の見出しには、プロパティの名前を添えます。見出しの下の小さな字の行は、そのプロパティの定義です。● の後に、仕様の定義の表にある「初期値 (Initial)」「適用対象 (Applies to)」「継承 (Inherited)」を、取得した W3C の仕様の原文のまま (英語のまま) 載せ、行の終わりに定義の出どころの仕様を添えます。取得元と取得日は、付録「出典」にまとめています。付録 A のアンテナハウスの拡張 (-ah-) については、仕様の引用ではなく、Kumiori が何をどう組むかを Kumiori 自身の言葉で書いています。

見本は、細い枠の中が Kumiori で組んだ例 (組版例) で、その下の灰色の背景がコードです。コードの中の、黄色の背景の太字の部分が、その節で取り上げる指定です。組版例とコードは、同じ原文から作っています。同じ見本は、Kumiori のテスト (test/conformance.test.ts) でも 1 つずつ組んで、警告が出ないことを確かめています。

1.2対応状況

対応プロパティの主な値を、仕様のとおりに組む。まれな値や新しい値に対応していないことはあり、それは節の値の表の「Kumiori」の欄に書く。
一部主な使い方の中にも、扱わない値や組み合わせ、仕様と違う組み方がある (節の本文に書く)。
未対応無視する。対応していないプロパティは、第 16 章に名前を挙げて並べる。

1.3確かめ方

「対応」「一部」「未対応」は、次のように確かめました。プロパティを指定した文書と指定しない文書を Kumiori で読み込み、組版に渡す中身 (Kumiori の中の論理的な木) を比べます。指定しても中身が変わらなければ、そのプロパティは効かない (未対応) としました。中身が変わるものは、この文書の組版例で、仕様のとおりに組めていることを目で確かめています。

組版の処理は、Kumiori のコマンドの既定のスタイル (本の組版向け) のまま行っています。CSS の計算値は Kumiori の中のカスケードで決めます (ブラウザを使いません)。フォントは Kumiori の既定 (和文は Noto Serif JP・Noto Sans JP、欧文は Tinos・Arimo、等幅は Cousine、数式は STIX Two Math) です。

ページ

ページの大きさ、余白、柱とノンブルは、@page の規則で決めます。@page の規則は文書全体に効くので、この章では見本の代わりに、この文書そのもののスタイルシート (docs/conformance/html/kumiori-html-css.css) の一部を示します。

2.1ページの大きさ : size 対応

初期値 : auto (size — CSS Paged Media 3)

“This property specifies the target size and orientation of the page box’s containing block.”— CSS Paged Media 3 §7.1

長さ (幅と高さ)、A3・A4・A5・B4・B5・JIS-B4・JIS-B5・letter・legal・ledger などの名前、portrait・landscape の向きを解釈します。以下の例は、本書のページ (182mm × 257mm、B5 判) の指定です。

size の指定の無い文書 (auto・向きだけの指定を含む) の用紙は A4 です。この既定の用紙は、Node のコマンドの --page-size と、公開 API の pageSize で変えられます (size と同じ書き方: A5・A5 landscape・148mm 210mm)。メディアクエリ (@media) の width・height・orientation は、文書の size ではなく、この既定の用紙で評価します (CSS Paged Media 3 §7.1)。

@page {
  size: 182mm 257mm;
  margin: 20mm 18mm 18mm 18mm;
}

size の値の意味 (CSS Paged Media 3 §7.1)

値意味Kumiori
autoページボックスの大きさと向きを処理系が決めます (ふつうは、刷る用紙に合わせます)。対応
<length>ページボックスの大きさを絶対の長さで決めます。1 つなら幅と高さの両方 (正方形)、2 つなら幅と高さです。対応
A4ISO の A4 判 (幅 210mm・高さ 297mm) と同じ大きさにします。対応
JIS-B5JIS の B5 判 (幅 182mm・高さ 257mm) と同じ大きさにします。対応
letter北米のレター判 (幅 8.5 インチ・高さ 11 インチ) と同じ大きさにします。対応
ほかの名前 (A5・A3・B5・B4・JIS-B4・legal・ledger)それぞれの名前の用紙と同じ大きさにします。対応
portraitページを縦置きにします (短い辺が横になります)。対応
landscapeページを横置きにします (長い辺が横になります)。対応

2.2ページの選び方 : :first・​:left・​:right・​:blank 対応

“The :left and :right pseudo-classes only match left or right pages, respectively.”— CSS Paged Media 3 §4.2.1

文書の最初のページ (:first)、左右のページ (:left・:right)、強制改ページで生まれる空白ページ (:blank) ごとに、余白や柱を変えられます。この文書は、左ページの左下と右ページの右下にノンブルを置き、柱を変えています。

@page :right {
  @bottom-right { content: string(chapter) "　|　" counter(page); }
}

@page の :first・:left・:right・:blank の値の意味 (CSS Paged Media 3 §4.2)

値意味Kumiori
:first文書の最初のページに適用されます。対応
:left左ページに当たります (どのページも、ページの進む向きによって左か右のページに分けられます)。対応
:right右ページに当たります。対応
:blank強制改ページによって生まれた、中身の無いページに当たります (break-before・break-after の left・right・recto・verso だけが、このページを生みます)。対応

2.3名前付きのページ : page 対応

初期値 : auto 適用対象 : boxes that create class A break points 継承 : no (but see prose) (page — CSS Paged Media 3)

“The page property is used to specify a particular type of page (called a named page) on which an element must be displayed.”— CSS Paged Media 3 §8.1

表紙は名前 cover のページ (余白を無くす)、目次は front のページ (ノンブルをローマ数字にする)、章は章ごとに c1・c2… のページ (小口に章のツメを出し、章ごとにツメの位置を下げる) に置いています。名前が変わるところで改ページします。

.cover { page: cover; }
@page cover { margin: 0; }
@page c2:right { @right-middle { content: string(chapno); … } }

page の値の意味 (CSS Paged Media 3 §8.1)

値意味Kumiori
autoauto でない値を持つ、最も近い祖先の値を使います。ルート要素では、空の名前になります。対応
<custom-ident>要素を置くページの種類 (名前付きのページ) を指定します。必要なら強制改ページを入れ、その種類の新しいページを作ります。対応

2.4ページのマージンボックス 対応

“Page-margin boxes are boxes within the page margin that, like pseudo-elements, can contain generated content.”— CSS Paged Media 3 §5

余白の 16 のボックス (@top-left-corner から @left-bottom まで) に対応します。ボックスの幅と高さは CSS Paged Media 3 §5.3 の規則で決め、ボックスには罫線・背景・角の丸み・余白を付けられます。小口の章のツメは、@right-middle (左ページは @left-middle) のボックスに背景の色と角の丸みを付けたものです。

@page c2:right {
  @right-middle {
    content: string(chapno);
    margin: 11.61mm -4mm 197.39mm 5mm;
    background-color: #c3ccc8;
    border-top-left-radius: 2.5mm;
    border-bottom-left-radius: 2.5mm;
  }
}

マージンボックス (@top-left-corner など 16 のボックス) の値の意味 (CSS Paged Media 3 §5 (Table 1))

値意味Kumiori
@top-left-corner・@top-right-corner・@bottom-left-corner・@bottom-right-cornerページの上 (下) の余白と左 (右) の余白が交わるところの、大きさの決まったボックスです。対応
@top-left・@top-center・@top-right上の余白を埋める、幅の変わるボックスです。@top-center は、ページの左右の端の中央に置きます。対応
@bottom-left・@bottom-center・@bottom-right下の余白を埋める、幅の変わるボックスです。@bottom-center は、左右の中央に置きます。対応
@left-top・@left-middle・@left-bottom左の余白を埋める、高さの変わるボックスです。@left-middle は、ページの上下の端の中央に置きます。対応
@right-top・@right-middle・@right-bottom右の余白を埋める、高さの変わるボックスです。@right-middle は、上下の中央に置きます。対応

2.5ノンブル : counter(page)・​counter(pages) 対応

“Counters can be defined and controlled within an @page rule, and used as content in page-margin boxes. This is useful for maintaining a page count.”— CSS Paged Media 3 §6.1

page はページの番号、pages は文書のページの数です。@page の counter-reset・counter-increment で、番号を振り直せます。番号の書式には list-style-type の名前 (lower-roman など) を使えます。

@page front { @bottom-right { content: counter(page, lower-roman); } }

counter(page)・counter(pages) の値の意味 (CSS Paged Media 3 §6.1)

値意味Kumiori
pageページごとに 1 ずつ自動で増えるカウンターです。@page の counter-increment・counter-reset で変えられます。対応
pages文書のページの総数を値に持つカウンターです。値は変えられません。対応

2.6柱の文字 : string-set 対応

初期値 : none 適用対象 : all elements, but not pseudo-elements 継承 : no (string-set — CSS Generated Content 3)

“The string-set property contains one or more pairs, each consisting of an custom identifier (the name of the named string) followed by a <content-list> describing how to construct the value of the named string.”— CSS GCPM 3 §1.1.1

要素の文字 (content()・content(text)・content(before) など)、属性の値 (attr())、カウンター (counter()) を名前の付いた文字にして、マージンボックスの string() で出します。この文書は、章の見出しの文字を chapter、data-no 属性の値を chapno にしています。

h1.chapter { string-set: chapter content(text), chapno attr(data-no); }

string-set の値の意味 (CSS Generated Content 3 §2.7.1・CSS GCPM 3 §1.1.1)

値意味Kumiori
none要素は名前付きの文字を設定しません。対応
<custom-ident>設定する名前付きの文字の名前です。後に、その値の作り方 (<content-list>) を続けます。対応
<string>文字列をそのまま値にします。対応
content() / content(text)要素の文字 (white-space: normal として解釈したもの) を値にします。text が既定です。対応
content(before)要素の ::before の文字を値にします。対応
content(after)要素の ::after の文字を値にします。対応
content(first-letter)要素の最初の字 (::first-letter と同じ定め) を値にします。一部: 最初の字だけでなく、要素の文字全体を値にします
attr()要素の属性の値を値にします。対応
counter()・counters()カウンターの値を値にします。対応

string() の値の意味 (CSS GCPM 3 §1.1.2)

値意味Kumiori
firstそのページで最初に設定された値を使います。ページに設定が無ければ、ページに入るときの値を使います。既定です。対応
start要素がページの最初の要素なら、最初に設定された値を使います。そうでなければ、ページに入るときの値を使います。対応

first-exceptfirst と同じですが、値が設定されたページでは空の文字列にします。対応

2.7書式の付いた柱 : position: running()・​element() 対応

“position: running(custom-ident) removes the element (and associated ::before and ::after pseudo-elements) from the normal flow, and makes it available to place in a page margin box using element().”— CSS GCPM 3 §1.2.1

running() にした要素は本文から外し、マージンボックスの content: element() で、書式を保ったまま置きます。

.header { position: running(header); }
@page { @top-center { content: element(header); } }

position: running() の値の意味 (CSS GCPM 3 §1.2.1)

値意味Kumiori

content: element() の値の意味 (CSS GCPM 3 §1.2.2)

値意味Kumiori
element(<custom-ident>)running() で外した要素を、マージンボックスに置きます。対応
first・start・last・first-exceptページの中に同じ名前の要素が複数あるとき、どれを使うかを string() と同じ語で選びます。対応

2.8トンボと塗り足し : marks・​bleed 一部

初期値 : none (marks — CSS Paged Media 3)

marks に crop か cross を指定すると、仕上がりの角のトンボとセンターのトンボを両方描きます (crop と cross を分けません)。bleed で塗り足しの幅を決めます。bleed の auto は 0 にします (CSS Paged Media 3 では、marks に crop があるとき 6pt)。コマンドの --print でも、トンボと塗り足しの付いた PDF を作れます。

@page { marks: crop cross; bleed: 3mm; }

marks の値の意味 (CSS Paged Media 3 §7.2)

値意味Kumiori

  • スキームのある URL (RFC 3986 §3.1 の形: 英字の後に英字・数字・+・-・. が続き、: で終わる) は、その URL を開きます (PDF の URI の動作)。既定では、スキームが http・https・mailto・tel のものだけをリンクにします。ほかのスキーム (javascript:・data:・file:・独自のスキームなど) は、リンクにせずに字だけを組み、警告に知らせます。スキームは、ブラウザと同じく、前後の空白・制御文字と、タブ・改行を取り除いてから読みます。
  • 相対参照 (file.pdf・../doc/a.docx など) は、PDF の置き場所からの相対のファイルを開きます。PDF には別の PDF を開く動作 (GoToR。#page=N はそのページ、#名前 は名前付きの飛び先) を、ほかのファイルにはファイルを開く動作 (Launch) を使います (ISO 32000-1 §12.6.4)。既定では、相対の PDF だけをリンクにし、ファイルを開く動作 (PDF でないファイル・絶対パス・スキームの無い //host/…) はリンクにしません。

3.15変形 : transform・​transform-origin・​transform-box 一部

初期値 : none 適用対象 : transformable elements 継承 : no (transform — CSS Transforms 1)

ボックスとその中身を、描くときに移動・拡大縮小・回転・傾けます。2D の変換の関数 (translate()・translateX()・translateY()・scale()・scaleX()・scaleY()・rotate()・skew()・skewX()・skewY()・matrix()) と、その並びに対応します (CSS Transforms 1 §9.1)。translate・rotate・scale のプロパティにも対応し、translate、rotate、scale、transform の順に掛けます (CSS Transforms 2 §5・§6)。変換の原点は transform-origin (初期値は基準のボックスの中央)、基準のボックスは transform-box で決まります (content-box・fill-box は内容のボックス、border-box・stroke-box・view-box は border のボックス)。

変換は組版に影響しません (CSS Transforms 1 §3)。ボックスの位置と大きさ、まわりの中身の流れ、ページの分け方は、変換を掛ける前のままです。ページや段で分かれたボックスは、断片ごとに、その断片のボックスを基準に変換します (CSS Fragmentation 3 §5.5)。変換したボックスは、中の絶対配置のボックスの包含ブロックになります。変換したボックスの中のリンクは、変換した後の形を囲む矩形が押せる範囲になります。逆行列の無い変換 (scale(0) など) のボックスは描きません。

3D の変換 (matrix3d()・translate3d()・translateZ()・scale3d()・scaleZ()・rotate3d()・rotateX()・rotateY()・perspective() と、translate・rotate・scale の 3D になる値) は解釈しません。その要素には変換を掛けず、読み込みのときに未対応として知らせます。百分率を含む calc() の長さ、html・body と、表の行グループ (thead・tbody・tfoot) の変換も解釈しません (読み込みのときに未対応として知らせます)。::before・::after の変換には対応します。変換したボックスは文書の順のまま描きます (後に続くボックスより手前に描く並べ替えはしません)。変換したボックスが絶対配置の包含ブロックにできないボックス (表・flex・段組の中など。16 章) のとき、その外に組まれる絶対配置の子孫には変換が掛かりません。罫線を重ねる表 (border-collapse: collapse) のセルは、セルの罫線ごと変換します。

3.16不透明度 : opacity 対応

初期値 : 1 適用対象 : all elements 継承 : no (opacity — CSS Color 4)

ボックスとその中身をまとめて半透明にします (CSS Color 4 §3.3)。数 (0〜1) と百分率に対応し、範囲の外の値は 0〜1 に丸めます。ボックスと中身を 1 枚の絵にしてから重ねるので、中で重なっている所が濃くなることはありません (PDF は透明のグループを使います)。行の中の要素 (span など) にも効きます。組版には影響しません。opacity の付いたボックスは文書の順のまま描きます (後に続くボックスより手前に描く並べ替えはしません)。html・body と、表の行グループ (thead・tbody・tfoot) の opacity は解釈しません (読み込みのときに未対応として知らせます)。ページの余白のボックスの opacity は、透明を使わずに、色を白に混ぜて表します。PDF/X-3 は透明を使えないので、opacity を使うと警告を出します。

3.17背景の範囲 : background-clip・​background-origin・​background-attachment 一部

初期値 : border-box 適用対象 : all elements 継承 : no (background-clip — CSS Backgrounds 3)

background-clip は背景を描く範囲 (border-box・padding-box・content-box) を、background-origin は背景の画像の位置と大きさの基準の領域 (padding-box・border-box・content-box) を指定します (CSS Backgrounds 3 §2.7・§2.8)。どちらも、複数の背景の層ごとに指定できます。背景の色は、いちばん後ろの層の background-clip の範囲に塗ります (§2.2)。角の丸いボックスでは、その範囲のボックスの角の丸みで切り抜きます。一括指定の background にボックスの語を 1 つ書くと両方に、2 つ書くと 1 つ目が background-origin、2 つ目が background-clip になります (§2.10)。ブロック・表・表のセル・回り込み・絶対配置のボックスに効きます (行の中の要素の背景と、ページの背景 (html・body・@page) には効きません)。

background-clip の初期値は border-box なので、背景の色も画像も、罫線の下まで描きます。破線・点線・二重線や、透明・半透明の罫線では、線のすき間に背景が見えます。background-origin の初期値は padding-box なので、画像の位置と繰り返しの始まりは padding のボックスの左上のままで、繰り返す画像は、そこから罫線の下にも並びます。background-clip の text (CSS Backgrounds 4 の値) は解釈しません。background-attachment は scroll と local を同じに扱い (ボックスに付く背景)、fixed (仕様では、ページの媒体ではページボックスに固定し、どのページにも繰り返す。§2.5) は scroll と同じに描いて、読み込みのときに未対応として知らせます。

4.3配置 : position 一部

初期値 : static 適用対象 : all elements except table-column-group and table-column 継承 : no (position — CSS Position 3)

absolute と fixed は、top・right・bottom・left で位置を決めて、通常フローから外して置きます。fixed は、ページごとに同じ位置に置きます。absolute の位置の基準 (包含ブロック) は、position が static でない最も近い祖先の padding のボックスです (CSS 2.1 §10.1)。そうした祖先が無ければ、ページの本文領域です。top と bottom がどちらも auto なら、通常フローの中で置かれるはずだった高さ (static position) に置きます。基準のボックスがページをまたぐときは、top は最初の断片、bottom は最後の断片を基準にします。基準になる祖先、またはその祖先との間にある要素が、表・flex・grid・フロート・段組・縦書きのボックスかインライン要素のときは、祖先のボックスではなく本文領域を基準にします。ただし、上下の位置を指定せず左右の位置だけを指定した要素は、その側へのフロートとして置き、指定の位置に近づけます。幅を指定しない絶対配置のボックスは、中身に合わせた幅 (shrink-to-fit。CSS 2.1 §10.3.7) にします。

relative は、組んだボックスを top・left (指定が無ければ bottom・right の逆向き) だけずらし、前後のボックスの位置は変えません (CSS 2.1 §9.4.3)。中の絶対配置のボックスもいっしょに動きます。ずらすのはブロックボックスだけで、行の中の要素はずらしません。sticky は位置の基準にはなりますが、ボックスはずらしません。

文字 (結合文字や絵文字の並びは、その並び) ごとに、フォント名を先頭から順に探し、その文字を持つ最初のフォントで組みます (CSS Fonts 4 §5.2・§5.3)。空白や数字も同じで、前にあるフォントが持つ文字を、後ろのフォントで組むことはありません。読み込んでいないフォントの名前は飛ばします。総称の名前 (serif・sans-serif・monospace) は、並びの中のその位置で、Kumiori の既定のフォントの組 (和文は Noto Serif JP・Noto Sans JP、欧文は Tinos・Arimo・Cousine) に当てます。既定のフォントの名前 (Noto Serif JP・Noto Sans JP) も、総称と同じ組として、その位置で探します。欧文のフォントの名前 (Tinos・Arimo・Cousine と、字幅を合わせてある Times New Roman・Arial・Helvetica・Courier New など) は、読み込んだフォントと並べて書いたとき、その位置で欧文の既定のフォントに当てます。並びのどのフォントも持たない文字は、既定のフォント、並びに無い読み込み済みのフォント (--font・fonts で足したフォントなど) の順に探します。@font-face で読み込んだフォント (unicode-range・太さの範囲を含む) も使えます。フォントのファイルは TTF・OTF・WOFF・WOFF2 を読みます。WOFF・WOFF2 は、ふつうのフォントのファイル (TTF・OTF) に戻してから使い、PDF に埋め込みます (WOFF 1.0 §5・WOFF2 §5 の表の変換を元に戻します)。WOFF2 の書体の集まり (WOFF2 §4.2) は TTC に戻します。@font-face で書体の集まり (TTC と、WOFF2 の書体の集まり) を指したときは、最初の書体を使います。

5.4字形の選び方 : font-variant-caps・​font-variant-numeric・​font-variant-ligatures 一部

初期値 : normal 適用対象 : all elements and text 継承 : yes (font-variant-numeric — CSS Fonts 4)

small-caps (フォントにスモールキャップが無いときは大文字を縮めて作る)、数字の形 (oldstyle-nums・tabular-nums・slashed-zero など)、合字の有無 (common・discretionary・contextual) に対応します。font-variant-position の super・sub は、フォントの上付き・下付きの字形 (OpenType の sups・subs) があるときだけ使い、無いときは作りません (font-synthesis-position は解釈しません)。字は 1 字ずつ字形を引くので、字の並びで決まる差し替え (diagonal-fractions の分数、ordinal の序数、contextual の文脈依存の合字) は、フォントが 1 字で差し替えるものだけ効きます。font-variant-alternates・font-variant-emoji は解釈しません。

font-variant-east-asian は、東アジアの字の字形の版 (jis78・jis83・jis90・jis04、simplified・traditional)、字の幅 (full-width・proportional-width)、ルビ用の字形 (ruby) を、それぞれの OpenType の機能で選びます。一括指定の font-variant に書いた値も同じです。フォントにその機能が無ければ、字は変わりません (字形を作り出しません)。縦書きでは、ほかの font-variant-* と同じく、機能を当てません。ルビの注釈 (rt) の字には、当てません (UA の既定の font-variant-east-asian: ruby も、注釈の字には効きません)。

異体字セレクタ (U+FE00〜FE0F、U+E0100〜E01EF) は、直前の字と合わせて 1 つの字として組み、フォントが持つ異体字の並び (OpenType の cmap の Format 14) の字形を選びます (IVS・SVS。「葛」に U+E0100 を続けた並びなど)。フォントにその並びが無ければ、もとの字の字形で組みます。禁則・字の間・縦書きの字の向きは、もとの字で決まります。

基底の字に結合文字が続く並び (e に U+0301、「か」に U+3099 の濁点など) と、絵文字の並び (肌の色の修飾、ZWJ でつなぐ並び、国旗、キーキャップ) も、1 つの字 (UAX #29 の拡張書記素クラスタ) として組みます。ラテン文字・ギリシャ文字・キリル文字が基底の並びは、合成済みの 1 字 (NFC) をフォントが持てば、その字で組みます (分解形で書いたベトナム語・多調のギリシャ語も、合成済みの字と同じ字形・同じ幅になります。CSS Fonts 4 §5.3)。ほかの並びは、並び全体を 1 つのフォントに渡すので、フォントの位置合わせ (GPOS の mark) と字形の置き換え (GSUB) が効きます。並びの途中では、改行せず、字間 (letter-spacing) も両端揃えの空きも入れません。並びを持つフォントが無ければ、合成済みの 1 字 (NFC) に置き換えられるときはその字で、できなければ字ごとの字形で組みます。

タイ語、デーヴァナーガリーで書く言語 (ヒンディー語など)、韓国語 (ハングル) を組めます。既定のフォントにはこれらの字が無いので、その字を持つフォント (Noto Sans Thai・Noto Sans Devanagari・Noto Sans KR など) を指定します (@font-face、Node のコマンドの --font、API の fonts)。デーヴァナーガリーは、フォントの整形 (結合子音、レフ、前に置く母音記号、ヌクタ、ZWJ・ZWNJ での形の切り替え) を通した字形で組みます。タイ文字は、上下の母音・声調記号をフォントの位置合わせで重ね、SARA AM (U+0E33) の丸を声調記号の下に並べ替えます。ハングルは、音節の字のほか、つなぐ字母 (U+1100〜) の並びを 1 つの字として、フォントが合成した字形で組みます。語の間に空白を書かないタイ語は、実行環境の Intl.Segmenter の辞書で求めた語の境目で折り返します (UAX #14 の SA、CSS Text 3 §5)。語の境目は実行環境 (ICU の版) で変わることがあり、Intl.Segmenter の無い環境では語の境目で折り返しません。韓国語は、word-break: normal では音節の間でも、keep-all では空白でだけ折り返します (CSS Text 3 §5.1)。ハングルの語の間の空白は、フォントが文脈で決める幅 (OpenType の calt) にします。ハングルと欧字・数字の間には、text-autospace の空きを入れません (CSS Text 4 §8.4.1)。PDF には、字形の並びが字の並びと対応しない字に元の字の並び (ActualText) を付けるので、文字を取り出せます。

制限: 字形は 1 つの字 (書記素クラスタ) ごとにフォントに渡すので、字をまたぐフォントの処理は、欧字・タイ文字の字の組の詰め (kern)、欧文の合字、ハングルの間の空白のほかは効きません (タイ文字の U+0E24 と U+0E45 の合字など)。正しくない並び (基底の字の無い記号、母音の字に続く母音記号) に、点線の丸 (U+25CC) は補いません。両端揃えで伸ばすのは、タイ語・デーヴァナーガリーでは空白だけです (空白の無いタイ語の行は伸びません)。縦書きでは、タイ文字・デーヴァナーガリーは横倒しに、ハングルは正立で組みます。

ほかのインド系の文字 (ベンガル文字 (ベンガル語・アッサム語)・グルムキー文字 (パンジャーブ語)・グジャラート文字・オリヤー文字・タミル文字・テルグ文字・カンナダ文字・マラヤーラム文字・シンハラ文字) も、その文字のフォント (Noto Sans・Noto Serif の各文字で確認) を指定すれば組めます。結合子音、レフ、前・上下・左右に分かれる母音記号、ヌクタ、アヌスヴァーラなどの記号、ZWJ・ZWNJ での結合の切り替え、マラヤーラム文字のチル文字、タミル文字の合字、テルグ文字・カンナダ文字の下に付く子音、シンハラ文字のラカーランサヤ・ヤンサヤ・レパヤを、フォントの整形を通した字形で組みます。結合子音は 1 つの字の単位で、その中では折り返さず、字間 (letter-spacing) も両端揃えの空きも入れません。Unicode の既定の規則 (UAX #29) が結合子音をまとめない文字 (グルムキー・カンナダ、タミルの合字になる 2 つ、シンハラの ZWJ のある並び) も、1 つの単位にします (UAX #29 §3 の音節のあつらえ、CSS Text 3 §1.4)。語は空白で折り返し、音節の間のフォントの詰め (kern・dist) を当てます。ベンガル文字の、語の途中の音節の前に置く母音記号は、語頭の形にしません。縦書きでは横倒しに組みます。PDF から取り出した文字は、元の字の並びになります。

ラオ語、クメール語、ビルマ語 (ミャンマー文字。シャン語・モン語の字を含む)、チベット語も、その文字のフォント (Noto Sans・Noto Serif の Lao・Khmer・Myanmar、Noto Serif Tibetan で確認) を指定すれば組めます。前に置く母音記号、下に付く子音、積み重ね、キンジ、声調記号は、フォントの字形で組みます。語の間に空白を書かないラオ語・クメール語・ビルマ語の文は、実行環境の Intl.Segmenter で求めた語の境目で折り返します (語の境目は実行環境で変わることがあります)。ゼロ幅空白 (U+200B) でも折り返します。チベット語は、ツェク (音節の区切りの点) の後ろで折り返します。ミャンマー文字は音節を、ラオ文字は前に置く母音と子音を、1 つの字の単位にし、その中では折り返さず、字間も両端揃えの空きも入れません。これらのフォントは字の上下が大きいので、行の高さ (line-height) は大きめに指定します。モンゴル文字 (Noto Sans Mongolian で確認) は、横書きと縦書き (writing-mode: vertical-lr・vertical-rl) で、語の字がつながった形で組めます。自由変形選択子 (U+180B〜U+180D)、母音分離子 (U+180E)、接尾辞の前の幅の狭い空白 (U+202F) を扱います。PDF から取り出した文字は、元の字の並びになります。

これらの文字の制限: 字形は字の単位ごとにフォントに渡すので、前後の単位で字形を変えるフォントの規則は効きません (Noto Serif Bengali の、語の途中の母音記号 AA が語末の形になる、など)。ベンガル文字の語頭の形の区別は横書きだけで、語の途中で書式の変わる所では語頭の形になります。フォントの整形に使うライブラリが知らない新しい字 (Unicode 14 以降のテルグ文字のヌクタなど) やまれな並びには、点線の丸が付く・結合の形にならないことがあります。モンゴル文字は、フォントの文脈の規則の一部が当たりません。和文とこれらの文字の間に、和欧間のアキは入れません。

アラビア文字 (アラビア語・ペルシャ語) とヘブライ文字を、右から左へ組めます。既定のフォントにアラビア文字は無いので、その字を持つフォント (Noto Sans Arabic・Noto Naskh Arabic など) を指定します (@font-face、Node のコマンドの --font、API の fonts)。ヘブライ文字は、既定の欧文のフォント (Tinos・Arimo) でも組めます (母音記号 (ニクード)・カンティレーションの付いた文も。Noto Sans Hebrew・Noto Serif Hebrew などを指定することもできます)。字の並ぶ順は Unicode の双方向アルゴリズム (UAX #9。行ごとに並べ替えます) で決め、dir 属性 (HTML の UA スタイルシートの direction と unicode-bidi)・direction・unicode-bidi・bdi・bdo・dir="auto" に従います。段落の始めの側 (text-align の start と end、text-indent、margin-inline-start などの論理的なプロパティ)、リストの番号と印の側、dir="rtl" の表の列の順も、右から左になります。アラビア文字は、空白で区切られた語をまとめてフォントに渡し、語頭・語中・語尾・独立の字形と必須の合字 (ラーム・アリフなど) を選びます。色だけが違う行内要素の境目でも、つながりは切れません (CSS Text 3 §7.3)。アラビア文字の母音記号などの結合文字は、Unicode の UTR #53 の順 (シャッダの上に母音記号) で重ね、ヘブライ文字の点は、ダゲシュ・シン/スィンの点を母音記号より先にフォントに渡します (子音とダゲシュ・シンの点を合わせた字形を持つフォントで、その字形になります。HarfBuzz と同じ順)。どちらも、並べ替えるのはフォントに渡すときだけで、PDF から取り出す字は元の並びのままです。ゼロ幅非接合子 (U+200C。ペルシャ語) は、語を分けずに、前後の字をつながらない形にします。LRM・RLM などの見えない制御の字は、幅を持ちません。両端揃えは語の間の空白だけを広げ、letter-spacing はアラビア文字の語の中には入れません (CSS Text 3 §6.4.4・§7.2.1。ヘブライ文字には入れます)。縦書きでは、どちらも横倒しで、行の下から上へ進みます。アラビア文字は、横倒しの語としてつなげて組み、text-orientation: upright では 1 字ずつ独立の字形にします (CSS Writing Modes 3 §5.1.1)。PDF には、語 (ヘブライ文字は母音記号の付いた字) ごとに字の並び (ActualText) を付けるので、読む順の文字を取り出せます (poppler で確かめました。字は、ページに置いた順 = 左から右で書いてあります)。

制限: アラビア文字の語の途中では折り返しません (word-break: break-all、overflow-wrap: anywhere でも、語のまま次の行へ送り、行より長い語ははみ出します)。アラビア文字の語の中の字の順は、unicode-bidi: bidi-override でも変わりません (語の位置だけが変わります)。字を伸ばす両端揃え (カシーダ) はしません。目次の行のように、右から左の題・欧文・リーダー・数字が続くと、UAX #9 のとおり数字が欧文の側に並びます (題を bdi や fo:bidi-override で囲むと避けられます)。シリア文字・ターナ文字・ンコ文字など、ほかの右から左の文字は、確かめていません。

ベトナム語・ギリシャ語 (多調を含む)・ロシア語・ウクライナ語などのキリル文字の言語は、既定の欧文のフォント (Tinos・Arimo) で組めます (太字・斜体、字の組の詰め)。ベトナム語の字 (Latin Extended Additional) は、語のほかの字と同じ欧文のフォントで組み、和欧間の空きの対象にします。日本語の文書の中 (総称・既定のフォントの、和文のフォントと欧文のフォントの組) では、ギリシャ文字・キリル文字が 2 字以上続く語は、ラテン文字の語と同じく欧文のフォントで組み、和字との間に和欧間の空きを入れます (ハイフン・アポストロフィでつないだ語は 1 つの語。ラテン文字・数字・和字・空白で語は切れます)。単独の 1 字 (単位や記号として使うギリシャ文字など) は、和文のフォントが持てば和文のフォントで組み、和欧間の空きは入れません。語は 1 つの文字列の中で見るので、行内要素の境目をまたぐ語は境目で切れます。アンテナハウス互換の指定 (--style ah) では、語も和文のフォントのままです。分綴 (hyphens: auto) は、言語の指定が ru (ロシア語)・uk (ウクライナ語)・el (現代ギリシャ語。単調の綴り) の文でします。ベトナム語、多調の綴りのギリシャ語 (el-polyton)・古典ギリシャ語 (grc) は分綴しません。

合字は、フォントの合字の表 (OpenType の GSUB の Ligature Substitution) にある字の並びを、1 つの字形にします。並びの長さと字の種類は限りません。語をアイコンに置き換えるフォント (Material Icons の home・arrow_back・3d_rotation など) も、名前を書けばアイコンになります。標準の合字 (liga・clig) は既定で使い、任意の合字 (dlig)・歴史的な合字 (hlig) は、font-variant-ligatures の discretionary-ligatures・historical-ligatures か font-feature-settings で指定したときに使います。合字の途中では、改行せず、字間 (letter-spacing) も両端揃えの空きも入れません。PDF から取り出す文字は、元の語になります (1 つの字形に 2 つ以上の名前を持つフォントでは、その文書で先に出た名前)。

字間 (letter-spacing) が 0 でないときは、合字にしません (CSS Text 3 §7.2)。font-variant-ligatures で common-ligatures などと指定していても同じです。font-feature-settings で "liga" 1 などと明示した合字は、字間があっても使い、字間は合字の後ろに空けます (CSS Fonts 4 §7.2)。必須の合字 (rlig) は、font-variant-ligatures: none でも字間があっても使います (CSS Fonts 4 §6.4)。制限 : 縦書き (縦中横を含む) では、フォントの合字の表による合字にしません。空白をまたぐ並びは合字にしません。フォントが文脈依存の置き換え (GSUB の Contextual・Chained Contexts Substitution) で作る合字は、欧文の字の 2〜4 字の並びが 1 つの字形になるものだけ効きます。

5.6可変フォント : font-variation-settings・​font-optical-sizing・​font-stretch 一部

可変フォント (OpenType Font Variations。1 つのファイルに、太さ・幅などの軸を持つフォント) を、軸の値ごとのフォントとして使えます。@font-face で読み込んだフォントと、fonts の選択肢・--font で足したフォントのどちらでも使えます。TrueType の輪郭 (glyf と gvar の表) の可変フォントと、輪郭が CFF2 の可変フォント (OTF の可変フォント) の両方に対応しています。輪郭の差分をどちらの形でも持たない可変フォントと、字形を読めない CFF2 の可変フォントは、警告を出し、既定の形で組みます (軸の値は効きません)。

軸の値は、CSS Fonts 4 §7.2 の順に決めます。まず font-weight・font-stretch (font-width)・font-style から太さ・幅・傾きの軸の値を決め、@font-face の記述子の範囲と、フォントが持つ範囲に収めます。次に、@font-face の font-named-instance (名前の付いたインスタンス)、@font-face の font-variation-settings、font-optical-sizing の順に当て、最後に font-variation-settings プロパティの値を当てます。フォントに無い軸の指定は無視します。

5.7カラーフォントと絵文字 : font-palette 一部

初期値 : normal 適用対象 : all elements and text 継承 : yes (font-palette — CSS Fonts 4)

色の付いた字形を持つフォント (カラーの絵文字のフォント、色の付いた見出し用のフォント) を、色の付いたまま組みます。既定のフォントに色の付いたフォントは無いので、そのフォントを指定します (@font-face、Node のコマンドの --font、API の fonts)。字の送りと行の中の位置は、ほかのフォントと同じく、フォントの値 (hmtx など) で決まります。縦書きでは、絵文字は正立で組みます。字形の中の「文字の色で塗る」部分 (COLR の色の番号 0xFFFF、SVG の currentColor) は、color の色になります。ほかの部分の色は、color を変えても変わりません。

フォントの形式 (OpenType の表)Kumiori での扱い

PDF には、色の付いたフォントの字を Type 3 フォント (字形ごとの描画の手続きを持つフォント) として書きます。字は文字のまま残るので、PDF から取り出す文字は元の絵文字 (並びは、並びの全体) になり、検索・選択もできます。同じ字形を何度使っても、字形の定義 (と画像) は文書に 1 つです。グラデーションは PDF の網かけに、グラデーションの途中の不透明度と合成は PDF の透明の機能にします。PDF/X の出力 (API の toPdf の pdfx) では、字形の色も CMYK にします (画像は CMYK の画像にします。透明を使う字形があると、警告を出します)。文字の色に cmyk()・特色を指定したときは、字形の「文字の色で塗る」部分が、その色のまま出ます。画面 (Canvas) には、ブラウザが色を付けて描ける形式 (COLR・CBDT・sbix) はブラウザのフォントの描画で、パレットを指定した字と SVG の形式の字は、PDF と同じ図形で描きます。API の renderPage は、どの形式も PDF と同じ図形で描きます。

font-palette は、フォントの中の色の組 (CPAL のパレット) を選びます。normal は 0 番のパレット、light・dark は、明るい背景向け・暗い背景向けの印の付いた最初のパレット (無ければ 0 番)、--名前 は、@font-palette-values の規則で決めたパレットです。@font-palette-values の規則は、font-family (その規則を当てるフォント)、base-palette (もとにするパレットの番号か light・dark)、override-colors (番号と色の組の並び) を読みます (CSS Fonts 4 §9.2)。同じ名前の規則をフォントごとに書け、同じ名前・同じフォントの規則は、後のものを使います。font の一括指定では、font-palette は変わりません。

絵文字の表示の切り替え : 字の後ろの異体字セレクタ U+FE0F (絵文字の表示) の付いた並びは、色の付いたフォントで、U+FE0E (文字の表示) の付いた並びは、色の付いていないフォントで組みます (読み込んだフォントの中に、その字を持つものがあるとき。UTS #51、CSS Fonts 4 §5.3)。どちらも付いていない字は、font-family の並びで選んだフォントで組みます。どのフォントにも無くて後備のフォントを探すとき、既定で絵文字の表示になる字 (Unicode の Emoji_Presentation の字) は、色の付いたフォントを先に探します。

中国語 (簡体字・繁体字)指定が要る (Noto Sans SC・TC、Noto Serif SC・TC)。既定の和文のフォントは、簡体字だけにある字を持ちません。字の間で折り返します。lang が zh の文に、中国語の改行の決まり (6.6 節)、圏点を字の下に置く既定 (7.2 節)、引用符 (10.5 節) が効きます。句読点の詰め方は、フォントの字形の位置で決めます (6.11 節)。正立。句読点は、フォントの縦書き用の字形に従います (8.1 節)。注音符号を親文字の右に置くルビ (横書きの ruby-position: inter-character) には、対応していません (9.1 節)。
韓国語 (ハングル)指定が要る (Noto Sans KR)音節の間でも折り返します (word-break: keep-all では、空白でだけ)。つなぐ字母 (U+1100〜) の並びは、1 つの字に合成します。正立ハングルと欧字・数字の間に、和欧文間のアキは入れません。
ラテン文字 (英語、ベトナム語など)既定 (Tinos・Arimo。等幅は Cousine)空白で折り返します。分綴は、英語とラテン語 (6.7 節)。分解形 (NFD) で書いた字も、合成済みの字と同じに組みます。横倒し (8.2 節)ベトナム語など、ほかの言語の語は分綴しません。
ギリシャ文字 (多調を含む)既定 (Tinos・Arimo)空白で折り返します。分綴は、現代ギリシャ語 (el。単調の綴り)。日本語の文書の中では、2 字以上続く語を欧文のフォントで組みます。横倒し多調の綴り (el-polyton) と古典ギリシャ語 (grc) は、分綴しません。
キリル文字 (ロシア語・ウクライナ語など)既定 (Tinos・Arimo)空白で折り返します。分綴は、ロシア語 (ru) とウクライナ語 (uk)。日本語の文書の中の語の扱いは、ギリシャ文字と同じです。横倒しほかの言語の語は分綴しません。
ヘブライ文字既定 (Tinos・Arimo)。Noto Sans Hebrew・Noto Serif Hebrew も指定できます。右から左へ組みます (UAX #9。8.4 節)。母音記号 (ニクード)・カンティレーションの付いた文も組めます。横倒しで、行の下から上へ進みます。目次の行のように、右から左の題・欧文・リーダー・数字が続くと、数字が欧文の側に並びます (UAX #9 のとおり)。
アラビア文字 (アラビア語・ペルシャ語)指定が要る (Noto Sans Arabic・Noto Naskh Arabic)右から左へ組みます (8.4 節)。空白で区切った語をまとめてフォントに渡し、前後につながる字形と必須の合字にします。横倒しの語として、つなげて組みます (正立の指定では、1 字ずつ独立の字形)。語の途中では折り返しません (行より長い語は、はみ出します)。字を伸ばす両端揃え (カシーダ) はしません。
デーヴァナーガリー (ヒンディー語など)指定が要る (Noto Sans Devanagari)空白で折り返します。結合子音は 1 つの字で、その中では折り返しません。横倒し字をまたぐフォントの処理は、効きません。正しくない並びに、点線の丸 (U+25CC) は補いません。
ベンガル文字 (ベンガル語・アッサム語)、グルムキー文字 (パンジャーブ語)、グジャラート文字、オリヤー文字、タミル文字、テルグ文字、カンナダ文字、マラヤーラム文字、シンハラ文字指定が要る (Noto Sans・Noto Serif の、それぞれの文字のフォント)空白で折り返します。結合子音は 1 つの単位で、その中では折り返しません。横倒し前後の単位で字形を変えるフォントの規則は、効きません。新しい字 (Unicode 14 以降のテルグ文字のヌクタなど) やまれな並びに、点線の丸が付くことがあります。
タイ文字 (タイ語)指定が要る (Noto Sans Thai)語の境目 (実行環境の Intl.Segmenter の辞書) と空白で折り返します。横倒し語の境目は、実行環境 (ICU の版) で変わることがあります。Intl.Segmenter の無い環境では、語の境目で折り返しません。空白の無い行は、両端揃えで伸びません。
ラオ文字、クメール文字、ミャンマー文字 (ビルマ語。シャン語・モン語の字を含む)指定が要る (Noto Sans・Noto Serif の Lao・Khmer・Myanmar)語の境目 (Intl.Segmenter)、空白、ゼロ幅空白 (U+200B) で折り返します。確かめていません。語の境目は、実行環境で変わることがあります。フォントの字の上下が大きいので、行の高さを大きめに指定します。
チベット文字指定が要る (Noto Serif Tibetan)ツェク (音節の区切りの点) の後ろで折り返します。確かめていません。フォントの字の上下が大きいので、行の高さを大きめに指定します。
モンゴル文字指定が要る (Noto Sans Mongolian)語は 1 つの単位で、字がつながった形になります (語の途中では折り返しません)。縦書き (vertical-lr・vertical-rl) でも、語をつなげて組みます (字は横倒し)。フォントの文脈の規則の一部が、当たりません。
絵文字指定が要る (Noto Color Emoji などの色の付いたフォント、Noto Emoji などの単色の輪郭のフォント)絵文字の並び (肌の色の修飾、ZWJ でつなぐ並び、国旗、キーキャップ) は 1 つの字で、その途中では折り返しません。正立色の付いた絵文字のフォント (Noto Color Emoji など。COLR・CBDT・sbix・SVG) は、そのフォントを指定すれば色の付いたまま組めます (5.7 節)。字 + U+FE0F は色の付いたフォント、字 + U+FE0E は色の付いていないフォントで組みます。font-variant-emoji は解釈しません。
そのほかの文字 (シリア文字・ターナ文字・ンコ文字などの右から左の文字、タイ・ルー文字など)確かめていません。

分綴 (hyphens: auto) の規則を持つ言語は、英語 (en・en-US・en-GB)、ラテン語 (la)、ロシア語 (ru)、ウクライナ語 (uk)、現代ギリシャ語 (el。単調の綴り) です。ほかの言語の語は分けません (6.7 節)。

可変フォント (1 つのファイルに、太さなどの軸を持つフォント) は、TrueType の輪郭のものも、輪郭が CFF2 のもの (OTF の可変フォント) も使えます。font-weight・font-stretch・font-variation-settings などで、軸の値を選べます (プロパティと軸の対応は 5.6 節)。

タイ文字・ラオ文字・クメール文字・ミャンマー文字・チベット文字・モンゴル文字、デーヴァナーガリー以外のインド系の文字、アラビア文字・ヘブライ文字の字形と位置は、同じフォントを HarfBuzz で組んだ結果と比べています。

文字ごとの見本

表の文字を、それぞれのフォントで組んだ見本です。文は、世界人権宣言の第 1 条の、それぞれの言語の訳です (Unicode コンソーシアムの「UDHR in Unicode」に収められた文)。行の頭の灰色の字は、その段落の言語の指定 (lang 属性の値) で、見本の中の CSS が attr(lang) で出しています。既定のフォントに無い文字のフォントは、@font-face で、Google Fonts の配信元 (fonts.gstatic.com) の、版の付いた URL から読み込んでいます。フォントのファイルを文書と一緒に渡すときは、src にそのファイルの名前を書きます。オリヤー文字の見本は、ありません。

10.6最初の字と最初の行 : ::first-letter・​::first-line 対応

::first-letter は、段落の最初の字 (前後に付く約物を含む) に書式を当てます。float: left にすると、何行かにわたる大きな頭文字 (ドロップキャップ) になります。::first-line は、段落の最初の行の字に書式を当てます。

最初の字を大きくして回り込ませ、最初の行を太字にした段落です。段落の始まりを目立たせるときに使います。2 行目からは普通の太さに戻ります。

initial-letter (CSS Inline 3 §7) は、::first-letter の字を、行の数で決めた大きさにして沈めます。initial-letter: 3 は 3 行分の大きさで 3 行に沈め (ドロップキャップ)、initial-letter: 3 2 は 3 行分の大きさで 2 行だけ沈めて 1 行分を上へ出し、initial-letter: 3 1 (3 raise) は沈めずに上へ出します。大きさは整数でなくてもかまいません。字の大きさは、font-size ではなく、段落の line-height と書体の値から決めます (§7.5.3): initial-letter-align が alphabetic (初期値) なら、字の大文字の高さの上端を最初の行の大文字の高さに、基線を N 行目の基線に合わせます。ideographic (lang が ja・zh・ko の文書の既定) なら、最初の行の字の枠の上端から N 行目の字の枠の下端までにします (ideographic-ink の位置は、字の枠で代えます)。leading は、最初の行の上端から N 行目の下端までです。漢字・仮名・ハングルの字は字の枠で、ほかの字は大文字の高さと基線で合わせます。大文字の高さは書体の OS/2 の表の値で、無ければ 0.66em です。縦書きでは、字を行の始め (上) に置き、字の枠で合わせます。最初の行の字下げ (text-indent) は字ごと下げ、字の余白 (margin)・枠・背景は回り込む範囲に入ります。短い段落の字は、続く段落まで回り込みが続きます。

制限: ::first-letter への指定だけに対応します (行の最初の span・画像への指定は警告で知らせます)。initial-letter-align の hanging・border-box は未対応です (alphabetic として組み、警告で知らせます)。initial-letter-wrap は未対応で、行はいつも字の箱の端にそろえます (none)。字の箱は、字の送り幅 (字の枠) で、字形の輪郭には合わせません。float を指定した ::first-letter には効きません (§7.3.1 の注)。字の箱は 1 つの回り込みとして置くので、段落の最初の行だけがページの終わりに入るとき、行は widows・orphans の決まりで次のページへ送られても、字が前のページに残ることがあります (字の箱と orphans の行が入らなければ、段落ごと次のページへ送ります)。

段落の最初の字を 2 行分の大きさにして、2 行に沈めた段落です。字の大きさは、行の高さと書体の値から決まります。字の枠の上端は 1 行目の字の枠の上端に、下端は 2 行目の字の枠の下端にそろいます。

3 行分の大きさの字を 2 行だけ沈めた段落です。字は 1 行分だけ上へ出て、最初の行はその分だけ下がります。回り込むのは 2 行で、3 行目からは左端から始まります。

HTML の中に直に書いた svg 要素を、画像のファイルの SVG (15.1 節) と同じに解釈し、PDF にベクターのまま描きます。大きさは svg 要素の width・height 属性で決め、行の中では画像と同じに置きます。下の例は、折り返すグラデーション (spreadMethod="reflect") と字を描いた SVG です。

文書の CSS は、svg 要素とその中の要素にも効きます (SVG 2 §6.4)。対応するプロパティは、fill・stroke・stroke-width・fill-opacity・stroke-opacity・opacity・fill-rule・stroke-linecap・stroke-linejoin・stroke-miterlimit・stroke-dasharray・stroke-dashoffset と color です (これらは SVG の要素にだけ効きます。HTML の要素の箱には効かず、継承して中の svg 要素に届くだけです)。SVG の属性 (fill="…" など) は詳細度 0 の規則として扱うので、文書の CSS の規則が属性に勝ちます (SVG 2 §6.6)。currentColor は、その要素の color の値で、svg 要素の外の color も継承します (CSS Color 4 §6.4)。sanitize.css の svg:not([fill]) { fill: currentColor } のように、アイコンの色を文書の CSS で決める書き方ができます。文書の CSS のほかのプロパティ (transform・display・font など) は、svg 要素の中の要素には届きません。

15.4数式 : math (MathML) 対応

“MathML is a markup language for describing mathematical notation and capturing both its structure and content.”— MathML Core, Abstract

HTML の中の math 要素を、OpenType の MATH の表を持つ数式のフォント (STIX Two Math) で組みます。分数・根号・上付きと下付き・上下の添え字・括弧の伸縮・行列 (mtable) に対応します。display="block" の数式は独立した行に、そうでない数式は本文の行の中に置きます。

A.13改ページと行グリッド : (-ah-)break-before・​(-ah-)break-after・​(-ah-)break-inside・​-ah-baseline-grid 一部

break-before・break-after・break-inside は、標準のものと同じに解釈します (14.1 節)。-ah- の拡張の値 even-document・odd-document を含む宣言は、解釈できない値として宣言ごと無視します。-ah- を付けた名前 (-ah-break-before など) は解釈しません。

-ah-baseline-grid は、行グリッドを作ります。new はその要素のフォントサイズと line-height で、root は根元の要素の書式で行グリッドを作り、中の行のベースラインを行グリッドにそろえます。none は行グリッドを解除します。-ah-baseline-block-snap は解釈しません。下の例の左は -ah-baseline-grid: new のボックスで、大きい見出しの後の行も、背景の線 (行グリッド) の上にそろいます。

A.14解釈する -ah- の拡張の範囲

Kumiori が解釈する -ah- の拡張は、A.1〜A.13 で取り上げたものです。「対応」は、Kumiori がそのプロパティを解釈することを表し、すべての値に対応しているとは限りません (値ごとの扱いは、各節の表の「Kumiori」の欄にあります)。(-ah-) と記した名前は、-ah- を付けない標準のプロパティとしても書けるものです。Kumiori はその多くを、-ah- を付けない名前の標準のプロパティとして解釈します (付けた名前も解釈するか、付けない名前だけかは、各節に書いています)。

そのほかの -ah- のプロパティ

A.1〜A.13 で取り上げた以外の -ah- のプロパティは解釈しません。読み込みのときに「知らない CSS のプロパティ」としては数えず (接頭辞付きの名前は数えません)、警告も出さずに黙って無視します。

互換の設定

HTML の既定のスタイルは、コマンドの --style (画面では「既定のスタイル」) で選びます。kumiori (本の組版向け、既定)、browser と browser-margin (ブラウザの既定)、ah (AH Formatter 互換)、vivliostyle、weasyprint があります。どれも既定のスタイルシートを選ぶもので、作成者スタイルシート (文書が <link>・<style>・style 属性で付けた CSS) が優先します。XSL-FO の互換の設定 (--compat antenna・--compat spec) は、「XSL-FO 1.1 編」の付録にあります。

--style ah は、AH Formatter の CSS の組み方に合わせる設定で、CSS 2.1 の付録の既定のスタイルシートに加えて、主に次の組み方を変えます。仕様と違う組み方は、この設定のときだけ使います。

項目--style ah での組み方
和欧文間のアキ1/4 em (Kumiori の既定は字の大きさの 1/8。CSS Text 4 の text-autospace の既定は 1/8 ic)。
空白ページの名前空白ページを、前のページと同じ名前付きページとして扱う。
名前付きページの :first名前付きページの組の最初のページに当てる。
脚注脚注の番号を本文の外に出す。脚注の参照番号の行の高さは、参照番号を置いた所の要素から継承する。
段組のボックス最初の子の上の余白と、最後の子の下の余白を段の高さに数えない。
表collapse の外枠の罫線のはみ出し、rowspan のセルの中央そろえ、自動レイアウトの列の幅を AH に合わせる。caption と表ヘッダーを、本体の最初の行と同じページに置く。
行の高さlang が日本語・中国語・韓国語の行のベースラインを、和文の字のフォントの上下で決める (CSS Inline 3 では、最初に使えるフォント)。
罫線thin・medium・thick の太さと、dot-dash・dot-dot-dash・wave の線種を AH に合わせる。罫線の太さを画素に丸めない (groove・ridge などの立体的な罫線の色は、どの設定でも AH に合わせる)。
leader()点を前の内容のすぐ後から並べる。
counter() の拡張content の counter(page physical) (名前に続けて physical を書く AH の書き方。文書の先頭から数えたページの番号) を解釈する。reverse は解釈せず、それを含む content は何も出さない。counter(page) は変わらない。
@page の中の字の大きさ@page の文脈の em などの基準の字の大きさを、AH の初期値の 10pt にする。
上付きvertical-align: super の上げ幅を、親の字の大きさの 1/3 にする (既定は 0.35)。
和文の組版text-autospace: none を「アキを入れない」と読み (AH の書き方)、段落の 1 行目の行頭の始め括弧類を詰める。
古い list-style-typebox・check・diamond・hyphen (古い CSS3 Lists の草案の書式) を記号として使う。
bolder・lighterフォントにある太さから、CSS 2.1 §15.6 の規則で決める (既定は CSS Fonts 4 の表)。
擬似要素の字の詰め::before・::after の中身と続く字の間で、字の組を詰めない。
