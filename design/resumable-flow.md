# 途中から組み直せる組版の設計の覚え書き (ページの境目で止めて、続きから組む)

Kumiori 0.7.0 の主題「途中から組み直せる組版」の設計です (計画の束 T0。台帳の API-04 の残りの段階 3・4)。
コードはまだ変えていません。作る束 (T2・T3・T4、流し書きの P2) は、取りまとめ役が見て、利用者が 9 節の問いを決めてから始めます。
この覚え書きは、リリースする文書 (`docs/` など) ではありません。

前提にしたもの:

- `design/relayout.md` (測った結果と段階 1〜5。段階 1・2 は 0.6.0 に入った)。速さの数は、そこの html-spec (HTML の対応仕様説明書 151 ページ) の値。
- `design/partial-and-streaming.md` (0 の「ページ N は N+1 を作った時に決まっている」、2 の `maxPages` の止め方、8 の同じになる条件)。
- main 7cf8a2b の `src/layoutEngine.ts` (12,783 行。うち `Flow` が 1466〜8572 行)。

## 0. 先に分かったこと (設計の形を決めるもの)

- **止める所は、もうある。** `maxPages` は、`notePage` で内向きの印 `PAGE_LIMIT` を投げ、`onceSteps` (1 段) と `layoutColumnPass` (段組) で受けて、
  そこまでのページで回を終える。ページ N は N+1 を作った時に決まっている (partial-and-streaming.md の 0)。
  **止めて捨てるだけなら、再帰の作りを変えなくてよい。** 難しいのは「続きから組む」方。
- **続きの位置は、再帰の呼び出しのスタックの中にある。** 改ページは、深い所 (行を置く `placeLine`、表の行を置く `placeRows` など) から
  `Flow.breakPage` → `PageHost.nextPage` を同期で呼んで起きる。`layoutChildren` の `ci` (いま何番目の子か)・行の並び `run`・
  `firstRun`・`topAt`、`layoutInlineRun` の何行目まで置いたか、`layoutTableRows` の `i` (行の番号)・`pending` (keep で繋がった行)、
  `splitRow` が作った断片の何番目か、などは、どれも関数の中の変数で、外から取り出せない。
- **前の組版と「揃った」かを見るだけなら、続きの位置は要らない。** 揃ったら、そこで止めて (`PAGE_LIMIT` と同じ形)、残りのページを前の組版から繋げばよい。
  したがって段階 4 (R7) は、2 つに分けられる:
  - **後ろを繋ぐ** (揃ったら止めて繋ぐ): ページの境目の状態を比べられれば作れる。直した所までは、いまどおり page-sequence の初めから組む。
    html-spec の真ん中 (74 ページ目) を直したとき、組むのは 1〜79 ページほど (半分)。
  - **前を飛ばす** (直した所の前のページの終わりから組む): 続きの位置を取り出して、そこから組み始められる流れが要る。組むのは 74〜79 ページほど。
- **ページの組版は、後ろの中身を読んでいる。** keep-with-next の試し組み (`keepWithNextBreak`)・分けない指定の試し (`holdKeepTogether`・`keepTogetherCheck`)・
  widows・行の高さを測る組み (`rowHeightRecord`)・段の釣り合わせは、いまのページより後ろの節を組んでみて決める。
  そのため「直した節より前のページは同じ」とは限らない。ページごとに「組むときに読んだ、いちばん後ろの節」(読んだ先。5.1) を覚え、
  読んだ先が直した節より前のページだけを、同じとみる。
- **組み直しの回 (ページ番号の確定) は、回ごとに比べる。** 1 回目の組版は、まだ置いていない参照先に仮の値 (いまのページ番号) を使うので、
  前の文書の収束した回と比べても揃わない。前の文書の、同じ回の境目と比べる (6.3)。
- **段組の page-sequence は、全体を何回も組み直して脚注・前方 float の予約を決める** (`layoutColumnSequence` が `layoutColumnPass` を 16 回まで)。
  ページの境目で止めて続けると、予約の決め方が変わる。0.7.0 では、段組の page-sequence は page-sequence の単位の使い回し (R6) だけにする (9 の問い 6)。

## 1. いまの組版の流れ

```
passSteps (組み直しの回。ページ番号の参照・ページごとの脚注番号・索引が前の回と同じになるまで、最大 5 回)
 └ onceSteps (1 回の組版。page-sequence の繰り返し。境目で yield)
    ├ seqMemo が当たる page-sequence は、前の回のページをそのまま使う (開始ページ・左右・脚注の続き番号・参照の値・索引の並びが同じとき)
    └ 当たらなければ layoutSequence (1 段) / layoutColumnSequence (段組)
       ├ 条件付きのマスター (last・only・rest) は、ページ数が収束するまで 3 回まで組み直す (needsLast)
       ├ layoutSequence: Flow を 1 つ作り、flow.layoutChildren(seq.flow.children) → finishPaginated
       │   Flow の中から PageHost.nextPage → mkPage (PageBuild を作る) → notePage (maxPages・進み具合)
       └ layoutColumnSequence: layoutColumnPass を予約が収まるまで (16 回まで)。群 (span) ごとに runColumnGroup、釣り合わせは試し組みの二分探索
 ├ 回の終わり: 全部のページの柱など (sheetStatics)。メモリ節約では page-sequence ごとに領域の木にして渡す (releaseLow)
 └ 収束したら finishTree (PageBuild → Area。手放す)
```

Flow の再帰 (主なもの): `layoutChildren` → `layoutBlockLevel` → `layoutBlock` (`openFrame` … `layoutChildren` … `closeFrame`)、
`layoutInlineRun` (行分けと行を置く)、`layoutTable` → `layoutTableRows` → `placeRows`・`splitRow` (セルごとにページを持つ Flow で組み直して断片に分ける)、
`layoutContainer` (ブロックコンテナ・絶対配置)、`layoutColumnsPaged` (箱の中の段組)、`layoutOrthogonalPaged`・`layoutRotatedPaged` (直交する箱)。
リストの項目は表の行で組む (`listMarkerRow`)。

## 2. ページの境目の状態

ページ N を閉じて N+1 を作る所 (`breakPage` の中の `nextPage` の前後) で、組版が持っている状態の全部です。
「置き場」は、いまどこにあるか。「取り出し」は、取り出して比べ・持ち出す方法。

### 2.4 続きから組めない所 (0.7.0)

次の所にページの境目が来たら、その境目は「続きから組めない」とし、記録しない (前の、組める境目か、page-sequence の初めから組む)。
結果を変えないための守りで、どのくらいの境目が組めるかは、作る段で数える (4.4 の `scripts/check-resume.mjs`)。

- 段組の page-sequence の中 (0 の最後)、箱の中の段組 (`layoutColumnsPaged`)、直交する箱・回した箱、
- 行の並びの途中の、書いた所に目印のある float・絶対配置の箱が、まだ置かれていない (`lineFloats`・`lineAbs`)、
- 分けない指定を、はみ出させて置いている間 (`keepHold`)、試し組み (`keepTrial`・`measureOnly`・`o.trial`)、
- `fo:retrieve-table-marker` のある表 (`layoutTableWithMarkers`)、行をまたぐセルを分けて組み直している表、
- 脚注を持たせる流れ (`holdFootnotes`) の中、メモリ節約の組み直し (`replaySink`)。

モジュールの数え (`staticAnchorSeq`・`floatAnchorSeq`) は、目印の鍵にだけ使い、出力に出ないので、境目の状態に入れない
(続きから組むと値が変わるが、同じ回の中で鍵が重ならなければよい。増やすだけなので重ならない)。

## 3. 作りの案の比べ

| 案 | 中身 | よい所 | 悪い所 |
|---|---|---|---|
| A. 生成関数 (`function*`) にする | `Flow` の再帰の関数を生成関数にして、`nextPage` で `yield` する | 止めるのは自然 (スタックがそのまま残る) | 止めた生成関数は写せない (前の文書の途中から、新しい文書で組めない)。行ごとに呼ぶ関数まで生成関数になり、行分けの速さが落ちる見込み (生成関数のオブジェクトを呼ぶたびに作る)。7,000 行の書き換え |
| B. 明示のスタック (状態機械) に書き直す | 再帰をやめ、作業の並びをループで回す | 位置が全部データになる | 7,000 行の作り直しで、組版の結果を 1 バイトも変えない条件では危うすぎる |
| **C. 続きの位置を記録し、飛ばしながら入り直す (推奨)** | 再帰はそのまま。各所が「いまの位置」を軽い記録 (2.2 の形) に書き、境目で写す。続けるときは、上から同じ関数を呼び、記録の位置まで子を飛ばし、写した箱の並びと欄を戻して、そこから組む | いまの関数の大部分がそのまま。位置が入力の節の添字の鎖なので、前の文書の位置を新しい文書に移せる (直した所の前は形が同じ)。組めない所は記録しないだけで逃げられる | 各所に「飛ばす」入口が要る (2.2 の 6 種類)。漏れると見えにくい誤りになる (4.4 の確かめで全部の境目を試す) |

WeasyPrint も、ページの続きの位置を、子の添字の入れ子 (`resume_at`) で返して、次のページを、その位置から上の箱から入り直して組む (公開のソースの作り)。
C はそれに近いが、Kumiori はページの中を 1 つの再帰で組み、改ページを深い所から呼ぶので、位置を返り値でなく記録で持ち出す。

## 4. 束 T2: Flow をページの境目で止めて、続きから組める形にする

### 4.1 条件

- **組版の結果を 1 バイトも変えない。** 続きから組む口を使わない組版はもちろん、組版の中で続きから組む所 (4.3) も、使わないときと同じ結果にする。
- 速さを落とさない (`perf:compare` で、どの文書も揺れの中。目安は +2% まで)。

### 4.2 形

```ts
/** ページの境目の記録 (ページ N を閉じ、N+1 を作る前) */
interface PageBoundary {
  /** page-sequence の番号と、その中のページの番号 (0 始まり。この境目の後に作るページ) */
  seq: number;
  index: number;
  /** 続きの位置 (2.2 の鎖)。外から順。続きから組めない境目は undefined */
  resume?: ResumeStep[];
  /** 2.1 の Flow の欄の写し (Frame は node を除く) */
  flow: FlowSnapshot;
  /** 2.3 の器の側の、回の初めからの数 (上限の数え・脚注の番号・lastIndex など) */
  engine: EngineSnapshot;
  /** 比べるための指紋 (5.3)。flow・engine と、続きの位置の節の番号から作る */
  digest: string;
  /** このページまでに組むときに読んだ、いちばん後ろの入力の節の番号 (5.1) */
  readTo: number;
}
```

- `breakPage` を、いまのページを閉じる所 (`closePage`: 開いた断片を閉じ、後ろの float・脚注を出す) と、次のページを開く所 (`openPage`: `nextPage`・
  欄を戻す・箱を開き直す・持ち越しの脚注と送った float を置く) に分ける。境目の記録は、その間で取る。続けるときは、記録を戻して `openPage` から入る
  (いまの `breakPage` の後ろ半分と同じ道を通るので、続きのページの初めの組みが、続けないときと同じになる)。
- 各所の位置の記録は、`Flow` が持つ `resumeStack` に、関数に入るときに積み、出るときに降ろす。ループの添字は、進めるたびに書く (数の代入だけ)。
  境目では、`resumeStack` の各段の値を写す (深さは 10〜30 ほど。ページごとに 1 度なので、軽い)。
- 続けるときは、`Flow` を記録の写しで作り、`layoutChildren(seq.flow.children)` を `resume` を持たせて呼ぶ。各所は、入口で `resume` の自分の段を取り、
  - 子の並び: `ci` を記録の値から始め、`run` は `children.slice(runAt, ci)` から作り直す。
  - ブロック・コンテナ: 箱を開かず、写した `Frame` を使う (`openPage` が開き直した断片)。
  - 行の並び: 字を平らにし、行分けまでを同じ入力で行い (行分けの覚えに当たる)、置いた行の数だけ、置かずに飛ばす。widows の送りは、記録の値を使う。
  - 表: 列の幅を測り直し (覚えに当たる)、行 `i` から。分けた行は `splitRow` を同じ条件で呼び直し、`frag` 番目から置く。
  - 自分の段を使い終えたら、`resume` を外す (それより後ろは、ふだんどおり)。

### 4.3 組版の中での使い道 (T2 の中で、いつも使う)

T2 の作り替えは、ほかの文書との使い回し (T3) の前に、1 つの文書の組版の中で次の 2 つに使う。**いつもの組版で通る道にするので、
`compare:base` (全部の文書の PDF のバイト列が同じ) と指紋の試験が、続きから組む作りをそのまま確かめる** (9 の問い 5)。

1. **最後のページのマスター (needsLast)**: いまは、ページ数を知って page-sequence を初めから組み直す (3 回まで)。最後のページより前のページの
   マスターは変わらないので、前の回の、最後のページの 1 つ前の境目から続けて組む (`lastIndex` を変えて `openPage`)。
2. **組み直しの回で、参照の値が変わった page-sequence**: いまは、字の差し替え (`reuseCites`) で済まなければ、page-sequence を初めから組み直す。
   ページごとの参照の記録 (5.2) から、値の変わった参照を初めて引いたページを見つけ、その前の境目から続けて組む。
   さらに、組んだ境目の指紋が、前の回の同じ所の指紋と揃ったら、そこで止め、前の回の残りのページを繋ぐ (6.2 と同じ作りを、回の間で使う)。
   fo-spec の目次の組み直し (1.1〜1.2 秒) は、目次の page-sequence の中で済む見込み (目次は前にあるので、効くのは後ろを繋ぐ方)。

  - `test/resume.test.ts`: 2.1〜2.3 の状態のそれぞれが境目にかかる小さな文書 (段落の途中・表の行の途中・分けた行の途中・脚注の持ち越し・送った float・
    retain の余白・break-after の後・マーカー・widows・ルビ・縦書き・XSL の余白・page-sequence の初めのページ番号・last のマスター)。

## 5. 比べる・繋ぐための記録

### 5.1 読んだ先 (ページが、後ろのどこまでの中身で決まったか)

- `documentNodes` (`indexDocument`) の通し番号 (入力の節の文書の中の順) を使う。`layoutBlockLevel`・行の並び・表の行・セルに入るたびに、
  `readTo = max(readTo, その節の番号の、部分木の終わり)` にする (試し組み・測る組みも同じ関数を通るので、読んだ分が入る)。部分木の終わりの番号は、
  通し番号を付けるときに一緒に覚える。比べ 1 つと代入 1 つなので、手間は小さい。
- 境目の `readTo` は、そのページまでで読んだ、いちばん後ろ。直した節の番号を `c` としたとき、`readTo < c` の境目までのページは、前の組版と同じ
  (入力が同じで、読んだ所が同じなので、組みは同じ。組版は決まった手順で、乱数・時刻を使わない)。

### 5.2 ページごとの記録 (繋ぐときに、そのページの分だけ足し直す)

ページごとに、組む間に器の側へ書いたものを並べて持つ: 置いた id (最初・最後)・id の物理のページ番号・脚注を置いた所・引いた参照と値と書式・
索引の点と並び・警告の範囲・maxPages の後ろを指す参照。繋ぐときは、残りのページの記録を、いまの器の側に順に書き足す
(いまの `seqMemo` が page-sequence の単位で行っていることを、ページの単位にする)。

### 5.3 指紋 (前の組版と揃ったか)

- 境目の指紋は、2.1 の欄 (保留の余白・捨てる印・区切り・送った float・持ち越しの脚注の番号と残りの高さ・まだ付けていないマーカー・開いている箱の
  `desc` と使った長さ)、2.3 の欄 (脚注の番号・lastIndex・上限の数えのうち 5.3 の扱いのもの)、続きの位置 (2.2 の鎖を、入力の節の番号に直したもの)、
  次のページの番号と左右 (sideDelta)、から作る短いハッシュ。持ち越しの脚注・送った float は、組んだ節の木を持つので、節の番号と高さだけを入れる
  (中身は入力の節で決まる。直した節を含むときは、続きの位置の比べで揃わない)。
- 前の組版と揃ったとみるのは、指紋が同じで、**次に組む位置が直した所より後ろ** (いまの位置の節の番号 − 直した所で増減した節の数 = 前の位置の節の番号、
  かつ、いまの位置が直した節の部分木の終わりより後ろ) のとき。
- 上限の数え (`nest.budget`・`condense`・`maxMeasureFlows`) は、回の初めから足していく数なので、直した所の後ろでは前の組版とずれ、そのままでは揃わない。
  そこで、数そのものでなく「上限に当たったか」(`hit`) を指紋に入れ、繋ぐときに「前の組版で、繋ぐページの分に使った数を、いまの数に足しても上限に
  届かない」ことを確かめる (届くなら繋がずに組み続ける。上限に当たる文書は悪い入力で、まれ)。

## 6. 束 T3: page-sequence の使い回し (R6) と、変わったページから組み直して繋ぐ (R7)

### 6.1 器が覚えるもの

`createTypesetter()` の器 (`reuse` が既定の true のとき) が、前の文書の組版の結果を 1 つだけ覚える (`PrevLayout`):

- 組み直しの回ごとに、page-sequence ごとの: 中身の指紋 (6.4)・始まりの条件 (開始ページ・左右・脚注の続き番号)・ページ (`PageBuild`)・境目の記録 (4.2)・
  ページごとの記録 (5.2)。
- `PageBuild` は、いまは `finishTree` で領域の木にした後に手放している (`releasePage`)。覚えるときは手放さない。
  **メモリは、前の文書の論理の木 1 つ分増える** (relayout.md の 5 の見込みと同じ。`lowMemory` の組版では覚えない。器の `reuse: false` で覚えない)。
  - 回ごとのページは、組み直しの回の多くが前の回のページを使い回す (`seqMemo`) ので、ほとんどが同じオブジェクト。字の差し替え (`reuseCites`) は、
    いまは前の回のページの行の節を書き換えるので、覚えたページを汚さないよう、書き換える行だけを写してから書き換える (書き換えは参照の字の行だけで小さい)。
- 前の文書の組版の結果を領域の木にした後 (`toPdf` などの後も) 持つので、結果のオブジェクトとは別に器が持つ。次の文書を組み終えたら入れ替える。

### 6.2 組み方

新しい文書の組版の、回 p の page-sequence s で:

1. **R6 (page-sequence の使い回し)**: 前の文書の回 p の s と、中身の指紋と始まりの条件が同じなら、前のページをそのまま使う (いまの `seqMemo` の
   当たりの扱いを、文書をまたいで行う)。参照の値が変わったら、いまの `reuseCites` と 4.3 の 2 で直す。
2. **R7 (変わったページから)**: 中身の指紋が違えば、前と新しい page-sequence の木を上から比べ、最初に違う節 `c` と、違う所で増減した節の数を求める。
   前の文書の回 p の境目のうち、`readTo < c` で、続きから組める、いちばん後ろの境目 k を選ぶ。境目 k までのページは前のものを使い、
   k の続きの位置を新しい文書の節に移して (直した所より前なので、添字の鎖は同じ)、そこから組む。
3. 組んだ境目ごとに、前の文書の回 p の、対応する境目 (同じページの番号で、直した所の後ろ) と比べ (5.3)、揃ったら止めて、前の残りのページを繋ぐ。
   揃わないまま page-sequence が終われば、いまどおり全部を組んだことになる (損は、比べの手間だけ)。
4. 後ろの page-sequence は、始まりの条件が揃えば R6 で使い回す。

前の文書の回の数と違う回 (前の文書は 2 回で収束し、新しい文書は 3 回目を組むなど) は、覚えが無いので、いまどおり組む (回の中の `seqMemo` は使う)。

### 6.3 ページ番号・相互参照のずれ

- **ページの番号が揃わないと繋がない** (推奨。9 の問い 4)。直した所でページが 1 枚増えると、後ろのページは番号が 1 ずれ、左右のマスター・柱・
  参照の値が変わりうる。揃うのは、ページが増減しない直し (字を足して行が増えても、5 ページほどで改ページの位置が元に戻るもの。relayout.md の 2.3) で、
  エディタで打つ直しの多くはこれ。
  - 広げる案: 番号がずれても、繋ぐページのどれでも選ぶマスター (左右・first・rest・last・白ページ) が前と同じなら、番号を付け直して繋ぐ。
    HTML の `@page :left`・`:right` のある文書は、1 枚のずれで左右が入れ替わるので繋げない。0.7.0 では入れず、作った後に数えて決める。
- **相互参照**: 繋いだページの記録 (5.2) から id のページを作り直すので、組み直しの回の判定 (`passSteps`) は、いまどおり働く。
  目次・索引・`target-counter()`・`page-number-citation` の値が変わったページは、次の回で 4.3 の 2 の作り (字の差し替え・値の変わった参照を初めて引いた
  ページの前の境目から続けて組み、前の回と揃ったら繋ぐ) で直す。直した所が目次の見出しなら、目次のページから組み、数ページで揃う見込み。
- **入力の節の番号** (`sourceRef`。領域の木の `sourceRef`・タグ付き PDF の構造の木の結び付き) は、組んだ節に数で入っている。直した所の後ろの
  ページは、増減した節の数だけずれるので、繋ぐときに、繋ぐページの節の木をたどって番号を直す (直した所より後ろの番号に、増減を足す)。
  診断の場所 (`withSource` の行・桁) も、直した所の後ろは入力の行がずれるので、ページごとの記録の警告は、節から場所を引き直す
  (ずれを直さないと、警告の行の番号が古いまま。T1 の組み比べで、警告の場所まで比べて確かめる)。
- 柱など (`sheetStatics`) は、いまどおり回の終わりに全部のページで組む (覚え `staticMemo` で軽い)。

### 6.4 中身の指紋 (LDocument の比べ)

- `indexDocument` が文書の節を順にたどる所で、節ごとの、組版に効く欄 (種類・字・書式の全部の欄・属性) のハッシュと、部分木のハッシュを作る。
  page-sequence の指紋は、その木と、ページのマスター・柱・脚注の設定・文書の全体の設定のハッシュ。
- 手間: 書式の欄の数が多い (`ResolvedStyle` ではなく、読み込みが付けた指定の欄)。html-spec で 100〜300ms の見込みで、組版の 5% を超えるなら、
  書式のオブジェクトごとにハッシュを覚える (読み込みは、同じ指定の要素で書式のオブジェクトを使い回すことが多い)。T3 のコミット 1 で測る。
- 前の文書の木と新しい木を、部分木のハッシュで上から比べ、最初に違う節と最後に違う節を求める (違わない部分木は降りない)。

## 7. 束 T4 が、作り直した流れにどう乗るか

### 7.1 深い入れ子の表 (閉じない `<li>`・`<td>`)

- いまの作り: 表の行は、まず行の高さを測る組み (`rowHeightRecord` → `layoutRowGroup`。セルをページなしの流れで組む) をし、ページに入らなければ、
  セルごとにページを持つ流れで組み直して断片に分ける (`splitRow`)。入れ子の段ごとに、測る組みと分ける組みの両方が中の段を全部組むので、
  分けられない段 (33 段より深い所。ページの残りが 1 行に足りない) では、段ごとに中身を全部測り直す (段の数 × 中身)。
- 作り直した流れの上の案: **分ける組みを、止められる流れで先に行う**。セルの流れ (`splitRow` の中の `Flow`) は、ページの残りに入らない所で止め、
  その境目の記録を持つ。
  - 入れば、その組みがそのまま行の組み (測る組みは要らない)。
  - 入らなければ、止めた所までが 1 つ目の断片で、続きは次のページで、境目の記録から続ける (いまは、続きの断片を `nextAvail` の高さを仮に決めて
    一度に全部組んでいる)。
  - 何も入らない (いまの null) ときは、最初の行で止まるので、中身の全部を組まない。これで、深い段の「段の数 × 中身」が「中身」になる見込み。
- keep-together・keep-with-next の行は、高さを知って決めるので、いまどおり測る組みをする。
- 結果が変わりうる所: 続きの断片を、仮の `nextAvail` でなく、本当の次のページの残りで組むので、表の行が 3 ページ以上にまたがり、ページの大きさが
  違う文書では、断片の分け方が変わりうる。そこで T4 は 2 つのコミットに分ける: (1) 入れ子の手間だけを直し、断片は今と同じ高さで組む
  (`compare:base` で全部の文書が同じ。hostileInputs の skip の 2 つを外す)、(2) 必要なら、続きの断片を本当の残りで組む (組み比べで変わる文書を一覧にする)。

### 7.2 脚注のあるリストの項目 (LAY-64)

- いまの作り: 項目は表の行で、行を分ける組み (`splitRow`) のセルの流れは、脚注を持たせるだけ (`holdFootnotes`) にして、外の流れが後で置く。
  分ける組みの上限 (`avail`) は、項目の中の脚注の高さを差し引いていないので、本文を詰めた断片が、脚注と合わせてページに入らず、
  項目ごと次のページへ送られ、次のページでも同じことが起きる、と見ている (原因の見当。T4 で確かめる)。
- 作り直した流れの上の案: 7.1 の「止められるセルの流れ」で、セルの流れの脚注を外のページの脚注の領域に数える (1 段のページの `pushFootnote` と同じく、
  脚注を置く余地のある所で止める)。T2 の境目の記録には、持ち越しの脚注 (`carry`) と脚注の番号があるので、断片の続きでも同じ番号・同じ続きで組める。
- 組版の結果が変わる (直したい所)。`compare:base` で変わる文書が、脚注のある項目のリストだけかを確かめる。

## 8. 束 P2 (流し書き) との口

P0 の担当が `design/pdf-writer.md` で PDF の書き手の API を決める。ここには、組版の側から出す口だけを書く。

### 8.1 確定したページ

- 回の途中のページは、次の回で変わりうる。**ページ j が確定するのは**、(a) 組み直しの回が収束したとき、または (b) 1 回目の組版の途中でも、
  ページ 1〜j の本文が、まだ置いていない参照先 (前向きの参照・本文の中の総ページ数・索引の並び・ページごとの脚注番号) を引いていないとき。
  (b) は、5.2 のページごとの参照の記録で分かる: 前を指す参照 (もう置いた id) の値は、後ろの組版で変わらない。
  - 前向きの参照を引いたページより後ろは、次の回で組み直しうる (4.3 の 2 で、そのページの前の境目から組み直し、揃えば繋ぐ)。
    確定を待つ間は、そのページの論理の木を持つ (目次を前付けに持つ文書は、目次のページから後ろが、収束まで確定しない)。
  - `maxPages` で止めた文書は、止めた回が最後なので、(a) で確定する。
- 柱など (static-content・ページの余白の箱) は、総ページ数 (`counter(pages)`)・`retrieve-marker`・ページ番号で変わる。柱に総ページ数を使う文書は、
  収束するまで柱が決まらない。本文と柱を分けて確定させる (下の 2 つの知らせ)。

### 8.2 口 (案)

```ts
interface PageSink {
  /** ページ j の本文が確定した (本文の論理の木 PageBuild と、領域の木にした本文。柱はまだ) */
  body(j: number, page: PageBody): void;
  /** ページ j の柱などが確定した (総ページ数・マーカーが決まった) */
  sheet(j: number, statics: SheetStatics): void;
  /** 組版の回が収束した (総ページ数が決まった。まだ知らせていないページは、この後に順に知らせる) */
  settled(total: number): void;
}
```

- 書き手は、`body` を受けたら、ページの中身の流れを書いて本文の論理の木を手放してよい (`releasePage`)。組み直しで、確定したページを
  組み直すことは無い (確定の決まりがそれを守る)。境目の記録 (4.2) と ページごとの記録 (5.2) は小さいので持つ。
- 柱が後で決まるページの書き方 (柱だけを後で書くオブジェクトにする・ページを書くのを柱が決まるまで待つ) は、P0 の決め。
  組版の側は、柱に総ページ数を使うかを、ページの柱の入力から先に知らせられる (`staticRetrieves`・`isPageInvariant` で、いまも調べている)。
- メモリ節約 (`lowMemory`) との関係: いまのメモリ節約は、収束まで組んだ後に、もう 1 度全体を組み直して (決まった回の組み直し `replaySink`)
  ページを渡す。流し書きを `PageSink` の形にすれば、確定したページを最後の回の組みから直に渡せるので、決まった回の組み直しが要らない文書が増える
  (前向きの参照の無い文書は、1 回の組版で渡し終える)。メモリ節約を `PageSink` に乗せ換えるかは、P2 で決める (結果は同じ PDF のバイト列にする)。
- 器の覚え (6.1) は、流し書きでは使わない (ページを手放すので覚えられない。`lowMemory` と同じ)。

### 12.1 続きの位置 (2.2) と、続きから組める所

- 段は 4 種類: 子の並び (`ChildrenStep`)・ブロック (`BlockStep`)・行の並び (`InlineStep`)・強制の区切り (`ForceStep`)。各段の `phase` が、
  下の段を呼んでいる所か、改ページを呼んだ所 (鎖の最後) か、そのどちらでもない (`''`) かを持つ。境目では、鎖を外から順にたどり、
  下の段と結び付いていること (子の並びの at 番目の子が、次のブロックの段の節、など) を確かめる (`Flow.resumeReason`)。
  **知らない所の改ページは、鎖の最後が改ページを呼んだ所にならないので、記録しなくても、続きから組めない境目になる** (漏れが誤りにならない)。
- 続きから組める改ページ (いま): 行を置く前・置いた後の改ページ (`placeInlineLines` の top・bottom)、行の前の保留の区切り (pending)、
  keep-with-previous・keep-with-next の改ページ (子の並びの kwp・kwn)、ブロックの break-before (pre)・分けない指定の試しの改ページ (ktc)・
  箱を開く所の、前の箱の break-after (open)、強制の区切りの段・白ページ・ページ・空のページの改ページ。
- 設計の 2.2 から**減らしたもの**: 本文の終わりの脚注だけのページ (finishPaginated) は、続きから組めない所にした。表 (行・分けた行) と
  ブロックコンテナは、初めの版 (0f163cb) では続きから組めない所にし、後で足した (14)。
- 2.4 の組めない所のほかに、次も組めない所にした: 脚注の試し組みの中 (`FootnoteCtx.inTrial`)、開いている箱が断片を集めている (`frags`。
  position: relative・絶対配置の基準の箱。境目の後で、前のページの断片を動かす) か、ドロップキャップの範囲を持つ。

### 12.2 境目の写し (2.1・2.3)

- Flow の欄は、配線の欄 (器・page-sequence が作って渡すもの) を除いて、全部を写す (`Flow.captureBoundary`。配列・Set・Map は 1 段だけ写す)。
  欄を足しても写し漏れが起きない形にした。開いている箱 (`Frame`) は写し、**まだ開いていない箱の節も写す** (境目の後で開いて中身を足すので。
  これを写さないと、続きから組んだとき、同じ節に行が 2 度入った)。子の並びの段が持つ行の並び (`run`) の配列も写す (境目の後で子を足すので)。
- 脚注の番号付けは、ctx を新しく作り、境目までに振った番号と積んだ印を移す (`FootnoteCtx.mark`・`adopt`)。組み直すときに新しい ctx で組むのと同じにするため
  (計測の覚えの鍵に ctx が入るので、前の ctx を使うと、覚えの当たり方が組み直すときと変わる)。
- 器の側は、ページごとの記録 (5.2 の `PageRecord`: id のページ・引いた参照と値・ページを作ったときの警告の数) を持ち、続きから組むとき、境目までのページの id を
  同じ順に書き直す。警告は、境目のときの数まで残す。
- 指紋 (5.3) は、写した欄・開いている箱・続きの位置・ページの数・脚注の番号・最後のページの番号・読んだ先から作る (`boundaryDigest`)。T2 では、
  境目に戻って同じ境目に来たときに同じかを確かめるのに使う (`resumeCheck`)。前の組版と揃ったかを見る使い方 (T3) では、比べる欄を絞る (5.3 の、
  回の初めからの数を差にする所) 必要がある。
- 読んだ先 (5.1): 子の並びで、行内の子は部分木の終わりまで (字を平らにして行に分けるときに読む)、ブロックは節そのもの (中身は、組むときにその子の並びで数える)
  を読んだとする (`sourceRefEnd`。設計の「部分木の終わり」では、1 つの大きな div の中の境目の読んだ先が、div の終わりになって使えないため)。
  試し組み・測る組みの流れも同じ記録 (`FlowHost.read`) に書く。

### 12.3 確かめ (4.4)

- 使う所: 組み直しの 1 回目の、文書の中の `seqMemo` が無い page-sequence。中身の指紋と始まりの条件が同じで、ページ番号の参照・索引・止めた組版の記録が無いもの。

  入力の節・`seq` を、この文書の同じ番号の節にする。警告の場所 (行・桁・要素) は、ずらした番号の節から引き直す。ページの画像を、画像の置き場に知らせ直す (`onUse`)。
- 確かめ: `scripts/check-relayout.mjs` (全部の群 240 文書・1200 版) で、使い回す器と使い回さない器の領域の木・診断・警告・PDF のバイト列が同じ。

## 18. 束 T3 の R7 (変わったページから組み直して、前の組版と繋ぐ) と、参照のある page-sequence の使い回しで作ったもの

### 18.1 作り (後ろを繋ぐ)

- 0 の「後ろを繋ぐ」と「前を飛ばす」(18.4) を作った。
- **直した所** (`ReuseMap`): 入力の節ごとの、節そのものの指紋 (`nodeTokens`。子の節には降りず、自分の番号からの差だけを入れる。部分木の終わりの差も入れる) の並びを、
  前の文書と比べ、初めの同じ所 (P 個) と終わりの同じ所の外を、直した所とする (前の文書の [P, oldEnd)、この文書の [P, newEnd))。初めの同じ所は同じ番号、
  終わりの同じ所は delta だけずれる。終わりの同じ所の節は、部分木ごと同じ (節の並びと形が指紋で決まる)。
- **前の組版の記録** (`SeqMemo.run`。`SeqRunRecord`): 器が覚えるとき、1 段の page-sequence の組みは、いつも境目を写し (`keep`)、境目の並び・ページごとの記録・
  組みの初めと終わりの警告の数・脚注の最後の番号・組んだページの数を、page-sequence の記録に持つ。前の文書から使い回した page-sequence (R6) と、
  最後のページのマスターで組み直す page-sequence は持たない。
- **揃ったか** (`spliceOk`): 新しい文書の組み直しの 1 回目で、中身の違う page-sequence を組む間、境目ごとに、前の組版の同じページの番号の後の境目と比べる。
  - 続きの位置 (`resumePos`) が直した所の後ろ (ブロック・表の節か、keep の改ページの後に組む子。行の並びは、その並びを持つブロック)。表の行の塊を置いている所は、
    まだ置いていない最初の行で、そのときは直した所が表の本体の行の中にあること (見出し・フッター・表の題は、続きのページでも組み直すので)。
  - 流れの欄の全部 (`captureBoundary` の写し。openPage が読む前に書き換える欄 `SPLICE_IGNORED` を除く。開いた箱の節は、openPage が読む欄だけ)・続きの位置の鎖
    (表の保留の行の位置は除く)・脚注の番号付け (振った番号と積んだ印) が、節の番号の対応の下で同じ (`sameMapped`: 入力の節は番号の対応、組んだ箱の `ref` は番号の対応、
    入力の節の欄の配列 (子の並び) は持ち主の節の対応、ほかは欄の全部を降りて比べる。関数・WeakMap など中を見られない物は、同じ物のときだけ同じ)。
    組んだ箱・セルを鍵にする覚え (`cellCols`・`cellAbs`・`flexItemCaps`) は、組んでいる表があるときだけ、鍵の組ごとに比べる (`SPLICE_SIDE`)。
  - 繋ぐページと警告が、直した所の中の節を指していない (`spliceCheck`)。行番号 (axf:line-number) の行のあるページは繋がない (番号をページをまたいで数えるので)。
  - ページ番号の参照: 繋ぐページの参照を、組み直しの 1 回目の決まり (置いた id はそのページ、まだ置いていない id と last・physical の参照は、引いたときのページ番号) で、
    繋ぐページの id を順に書きながら引き直し、ページに組んだ字の値と同じこと (`spliceCites`)。ページごとの記録の参照に、字の書式と引いたときのページ番号を足した。
- **先へ延ばす** (`SPLICE_LEAD`): 初めに揃っても、前の組版の次の境目があり、続きから組める間は、3 ページまで組み続けてから繋ぐ (揃った後の組みは前の組版と同じなので、
  繋ぐ所はどこでもよい)。繋いだ後ろの境目は次の文書のために覚えない (18.5) ので、次の文書が同じ所を直して、揃う所が少し後ろにずれても繋げるように、境目を後ろまで持つ。
- **繋ぐ** (`applySplice`・`spliceAdopt`): 揃ったら、組むのを止め (`SPLICE`)、前の組版の残りのページを、入力の節の番号をずらし、柱・マーカーの節と seq を付け替え、
  画像を知らせ直して繋ぐ。ページごとの記録 (警告の数をこの組みの数にずらす)・id のページ・警告 (場所を、ずらした番号の節から引き直す)・参照の記録 (引き直した値)・
  脚注の最後の番号を足す。
- ページの番号と左右がずれたら繋がない (D-066 の 4): 同じページの番号の境目どうしで比べ、始まりの条件 (開始ページ・左右・脚注の続き番号) が同じ page-sequence だけを試す。
- 段組の page-sequence は R6 だけ (D-066 の 6)。索引・止めた組版・ページごとの脚注番号・最後のページのマスターのある page-sequence は繋がない。
- 組む手間の上限の近くの文書 (前の文書の、回ごとの数えの最大の 2 倍に余裕を足すと上限に届くとき、と上限に当たったとき) は、R6 も R7 も使わない
  (使い回すと組む流れが減り、初めから組めば当たる所で当たらなくなる)。
- 効果 (opacity・transform・outline・clip。`paintEffect.ts`) のある文書も使う (R6 も)。組んだ箱の効果の印 `fxRef` (と、行内の枠の `outlineRef`・`linkRef`) も、
  入力の節の番号と同じく、比べるときは対応で比べ、繋ぐときはずらす (R6 は、この印をずらさなかったので、効果のある文書では使い回していなかった)。
- 索引のある文書は、R6・R7 とも使わない (6 の決めのまま) ので、境目を写さず、器も覚えない (手間を省く)。
- 器は、文書を組み終えたら、前の文書の組版を手放す (`endLayout`)。記録の中の閉包がこの文書の器を指すので、持ったままだと、前の前の文書も残りうる
  (fo-spec を器で何度も組むとヒープが回ごとに増えるのは、この作りの前からで、使い回しとは別 (索引のある文書は、使い回しも覚えもしない))。
- 節ごとの指紋 (`nodeTokens`) と、前の文書との番号の対応は、要る所 (中身の違う page-sequence を繋ぐか見るとき・効果の物を替えるとき) で初めて作る
  (中身の同じ文書を何度も組むときの手間を省く。作り始めた版では、表の大きな文書 (gen:table) を同じ中身で組み直すのが 1 割ほど遅くなっていた)。

### 18.2 確かめの作り (指紋が続きの組みを決める状態をすべて含むか)

- 比べるのは、写した流れの欄の全部 (欄を足しても、比べ漏れが起きない)。流れの外の状態 (器の側の id のページ・参照・警告・脚注の番号付け・上限の数え・
  最後のページのマスター・ページの番号と左右) は、1 つずつ比べるか、繋がない条件にした。
- **繋ぐ確かめ** (`resumeProbe.spliceVerify`): 揃っても繋がずに終わりまで組み、繋いだはずの前の組版のページ・id の記録・警告と、組んだものが、
  節の番号の対応の下で同じかを知らせる。違えば、比べる状態に漏れがある。`scripts/check-relayout.mjs --subjects reuse,splice-verify` と
  `test/relayoutSplice.test.ts` で使う。

### 18.3 参照のある page-sequence の使い回し (R6 を広げたもの)

- 組み直しの 1 回目で、前の文書の、中身の同じ page-sequence にページ番号の参照があっても、ページの参照を 18.1 の決まりで引き直し、ページに組んだ字と
  同じなら使い回す (`adoptPrev`)。参照の記録は、引き直した値で作り直す (初めから組んだときの記録と同じにする)。2 回目からの回は、いまどおり
  (`reuseCites` で字を差し替えるか、組み直す)。

### 18.4 前を飛ばす

- 新しい文書の組み直しの 1 回目で、繋ぐ相手のある page-sequence を組み始める前に、前の組版の境目のうち、そこまでを組むのに読んだ先 (`readTo`。5.1) が
  直した所より前 (P より前) で、続きから組め、組んでいる表の無い、いちばん後ろの境目 k を選ぶ (`skipFrom`)。そこまでのページは、いまの文書でも同じに組める
  (入力が同じで、読んだ所が同じ。始まりの条件と、組み直しの 1 回目の参照の値は確かめる)。
- 境目 k までのページを前の組版から使い (`spliceAdopt` を範囲で。ページごとの記録・id のページ・参照 (引き直す)・警告)、境目の写しを、いまの文書の物に移して
  (`remapBoundary`: 前の文書の入力の節は同じ番号のいまの節に、入力の節の欄の配列は持ち主の節の同じ欄に、それらを含む物は写して替える。含まない物 (書式・書体・
  組んだ箱) はそのまま。直した所より後ろの番号・関数を含めば移さない)、脚注の番号付けも節を替えて移し (`FootnoteCtx.adoptMapped`)、そこから続けて組む。
  その後は、後ろを繋ぐ作り (18.1) のまま。
- 移した境目は、次の文書のために、いまの文書の境目として覚える (同じ所を直し続けるとき、次の文書も同じ境目から飛ばせる)。k より前の境目は覚えない。
- 繋ぐ確かめ (`spliceVerify`) では飛ばさずに組み、境目 k で、そこまでのページ・id の記録・警告の数と、境目の状態が、前の組版と同じかを確かめる (`prefix: true`)。

### 19.2 前向きの参照のあるページの前を飛ばす (P-03 の 1) と、組み直しの 2 回目からの回の R7 (P-03 の 2・4.3 の 2)

- Typesetter が覚えるのを、組み直しの 1 回目の記録にした (`passOneMemo`)。2 回目からの回で組み直した page-sequence は、1 回目のページも持つ。
  2 回目からの回の字の差し替え (`reuseCites`) は、1 回目のページの字の節と参照の記録を書き換えるので、書き換える前の中身 (`CiteUndo`。初めに書き換える
  前のものだけ。節ごと・記録の項目ごと) を覚え、次の文書が前の文書を使うと決めたとき (`setupReuse`) に戻す。18.5 で考えた「書き換える行と上の箱を写してから
  書き換える」作りより小さい (ページの木は 1 つのまま。終わりの回に書き換える所 (行番号・書字方向の裏返し) は、もともと 2 度当てない印を持つ)。
- 2 回目からの回で、字の差し替えができない page-sequence は、前の回の組みの境目の記録を使い、同じ文書の前の回と繋ぐ (`SpliceTarget.within`。
  節の番号の対応はそのまま)。前を飛ばすのは、境目までに引いた参照 (ページごとの記録の、境目の前のページまで。境目の後のページの中身を先に組んで
  引いた参照も、引いたときのページの記録に入る) の値が、どれもいまの回と同じ境目 (`citesSameUpTo`)。後ろを繋ぐのは、境目の状態が前の回と同じで、
  繋ぐページの参照の値がいまの回と同じとき (`spliceCites` は、2 回目からの回は前の回の結果の値で引く)。入力が同じなので、直した所の位置の条件は見ない。
- 前の回の境目の記録は、Typesetter が覚えるとき (`reuseNow`) だけある (`typeset` の関数・`reuse: false` では、2 回目からの回も、これまでどおり組む)。
  前の文書の page-sequence をそのまま使い回した組み (R6) は、境目の記録が前の文書の節を指すので、2 回目からの回でも繋がない。
- 試しの種: `gen-stress-docs.mjs` の `REUSE_SHAPES` の `toc` (HTML)・`fotoc` (XSL-FO)。初めに目次があり、章が 10 ページ目より後ろに来るので、
  目次の値の桁が 1 回目と 2 回目で変わる。

### 19.3 ブロックの足し消し (P-03 の 3)

- 前は、節の指紋 (`nodeTokens`) が、子の節を自分の番号からの差で持ち、部分木の終わりの差も持つので、ブロックを足す・消すと、祖先の節 (本文・
  page-sequence・文書) の指紋がみな変わり、直した所 (`ReuseMap` の P) が文書の初めになった。直した page-sequence は、前を飛ばすのも後ろを繋ぐのも当たらなかった。
- 節の形 (`nodeShapes`) に、子の節を番号なしで字にした weak (配列の中の子の節は入れない) と、子の節を指す所の並び refs (指す節の番号と欄の道) と、
  部分木の終わり ends を足した。`diffShapes` は、初めの同じ所を weak で、終わりの同じ所を full で決め、初めの同じ所の節のそれぞれで、refs と ends を、
  直した所の外の番号の対応で照らす (直した所の中を指す所は R にし、配列の中の R は除く: 子の並びに足した・消した節は、直した所の中にある)。
  照らせない節があれば、そこを P にしてやり直す (入れ子を替える直し (A[a, X] → A[a[X]]) は、a の子の並びが照らせないので、a から直した所になる)。
- 祖先の節は、欄が同じで、子の並びの直した所の外が対応すれば、初めの同じ所に入る。前を飛ばす境目 (読んだ先が P より前) の写しは、祖先の節と、
  その子の並び (持ち主の節の対応で替える) の、直した所より前の位置を指すので、そのまま移せる。
- 後ろを繋ぐ所の比べ (`spliceSteps`) は、子の並びの中の位置 (`ChildrenStep` の at・runAt・topAt) と、表の行の塊を置く所の位置 (`TableRows` の i・end) を、
  位置の数でなく、その位置の子の節で比べる (`childAt`。前の子の並びにブロックを足す・消すと、後ろの位置の数はずれる。数のまま比べると、消した節の
  後ろの別の子を同じ位置と見ることもある)。字の子は位置の数のまま比べる (ずれれば揃わない)。
- page-sequence の節そのものが同じかは、前の full の指紋でなく、page-sequence の節が初めの同じ所にあることで見る。加えて、直した所が本文 (flow) の
  部分木の中にあることを見る (`spliceTarget`)。page-sequence の本文の外の節 (柱・領域の背景の箱 (XSL-FO の領域の background-color は、page-sequence の
  中の箱の節になる)・脚注の区切りなど) を足す・消す・直したときは、どのページにも効くので繋がない (18.10 のマスターの直しと同じ)。
- 試しの種: `relayout-check-lib.mjs` の `editBlock` (中に同じ名前の要素の無い fo:block・p・li を 1 つ消すか、すぐ後ろに同じものを足す)。
  `check-relayout.mjs` と `test/relayoutAlways.test.ts` の直しの並びの 5 回に 1 回ほど (`blockRate: 0.2`)。
